## Findings

Desktop already selects canonical repository context and renders host-observed
status/worktree/staged diffs. Its connection path builds a private registry
with `echo`, `fs.read`, observers, `repo.patch`, `repo.create-file`, and
`repo.edit-files`. It does not use `rah_cli::profile_composition::compose`,
does not retain `RepositoryCommitControl`, and does not wire stage, unstage,
commit authorization, `repo.commit`, or a post-commit result.

The existing `RepositoryCommitControl` captures an in-memory reviewed snapshot;
the model sees only a message-only `repo.commit` request. The current
implementation already refuses stale/consumed authorizations and verifies its
one commit result. Frontend/SQLite state cannot become authorization.

## Candidate method and authority reasoning

Candidates A–J were scored 1–5 using user value, workflow completion,
frequency, authority cost, security/cross-platform/recovery complexity,
deterministic/live feasibility, architecture fit, implementation size,
discoverability, operational burden, lock-in, and release risk. Cost/risk
dimensions score 5 as worse; value/testability dimensions score 5 as better.

The recommendation is Desktop end-to-end repository authoring/review/commit.
It has the highest user value and completion score while reusing existing
bounded authorities. It requires no ADR because it does not alter the accepted
authority contract. A stale displayed diff must never authorize a changed
index: Rust must re-observe/compare and capture only a current matching
snapshot after explicit human confirmation. Reconnect, repository/model
generation change, external relevant changes, resume, and restart invalidate
or fail pending state.
