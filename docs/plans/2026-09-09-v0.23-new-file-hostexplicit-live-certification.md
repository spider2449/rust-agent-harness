## Focused live evidence harness

The ignored Windows-only test is:

```text
tests::windows_live_desktop_hostexplicit_create_file
```

It uses a fresh disposable Git repository, an existing ordinary `src` parent,
and the absent logical target:

```text
src/rah-hostexplicit-live-created.txt
```

The source is bounded, deterministic, contains the privacy sentinel
`RAH_SECRET_CREATE_FILE_LIVE_CONTENT_SENTINEL`, has two LF line separators,
and intentionally has no final newline. Its byte length and SHA-256 are
derived in the test and checked against the direct complete review and the
final file.

The protected fixture has one unrelated staged modification. The test captures
HEAD, symbolic HEAD, branch, refs, raw index bytes, Git status/diffs, root and
parent directory entries, target absence from the worktree/HEAD/index, ignore
admission, and unsupported sparse state before Prepare. It establishes and
checks reviewed Commit authorization as fixture state; Prepare must preserve
it and Started must invalidate it.

The test calls the production connected-current Desktop composition,
`host_prepare_repo_create_file`, ticket-only
`host_confirm_tool_invocation`, shared preparer revalidation, D2, and
`authorized_tool_dispatch` into the current ToolRegistry. It does not directly
call the Tool, use a model turn, inject a model Tool call, or invoke a provider.

The generic Prepared and terminal HostActivity serializations are scanned by
value for the ticket, source, source hash, logical/native paths, parent path,
and raw source-bearing values. The direct Prepared response is intentionally
excluded from this generic scan because it is the local source-bearing review
surface required by ADR 0024. The test requires status-only terminal result,
duplicate consumed-ticket rejection, activity-ID rejection for Confirm and
Cancel, Idle coordinator/chat state, unchanged index/HEAD/branch/refs, no
Stage/Commit, zero model/chat activity, zero MCP/Process Plugin activity, and
the exact independent Tool/native counts.

Task 272 deterministic cancellation coverage is used instead of adding a
second live cancellation target; the primary live target remains a single
clean exactly-once effect path.

Because the existing live-test-support hooks covered multi-file operations but
not this Tool, two feature-gated process-local counters were added to
`rah-tools` for the existing `RepositoryFileCreationTool`: one at Tool entry
and one immediately before the native exclusive-create attempt. They expose
no production authority or logging surface and are unavailable in the default
crate build.

## Execution record

The successive fresh disposable repositories exposed only test-harness
assertion defects before the successful run: unset `core.sparseCheckout` was
mistaken for an error; the raw-index baseline was captured before Desktop
setup had finished its normal Git refresh; terminal status was compared at the
wrong serialization layer; Git porcelain status was compared in insertion
order rather than path order; and protected-state diagnostics were initially
too aggregate. Later effectful fresh runs narrowed the status and descriptive
refresh assertions. One final effectful fresh run showed that the refreshed
workflow may expose a new reviewable Commit snapshot, while the paired
authorization control correctly remains empty. The live assertion was changed
to require the security-relevant condition—no pending Commit authorization—
and to rely on Task 272 deterministic coverage for the review-state
transition. Every rerun used a new disposable repository and target; no
effectful target was retried.
