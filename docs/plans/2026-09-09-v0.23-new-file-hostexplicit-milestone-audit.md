## Six ADR 0013 result classes

A create-file terminal classification may cause only a descriptive repository
refresh while the captured repository context remains current. Refresh is not
authorization, retry, replay, or repair.

| Result | Commit point | Known RAH effect | Possible target state | HostActivity | Generic safe result | Refresh | Retry/replay | Cleanup/rollback |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| ok | Yes | Exact target verified | Exact bytes in one regular non-reparse file | tool_completed | status-only ok | Descriptive if current | No | No |
| invalid_target | No | No | No RAH target effect; invalid input/path | tool_error | status-only invalid_target | Descriptive if current | No | No |
| precondition_failed | No | No | No RAH creation; admission failed | tool_error | status-only precondition_failed | Descriptive if current | No | No |
| create_failed_known | No | No | External collision may remain; no RAH-created target proven | tool_error | status-only create_failed_known | Descriptive if current | No | No |
| write_failed_known | Yes | Exclusive create succeeded | Empty or bounded attributable prefix may remain | partial_effect | status-only write_failed_known with partial-file warning | Descriptive if current | No | No |
| uncertain | Possibly | Possible but not safely classified | Absent, empty, partial, complete, or replaced target may be possible | possible_effect_unknown | status-only uncertain; malformed output has no result | Descriptive if current | No | No |

create_failed_known requires bounded post-observation proving no RAH creation.
write_failed_known requires created-object identity, attributable prefix, safe
parent, and protected Git state. Lost verification, replacement, identity
mismatch, and malformed/contradictory output remain uncertain.

## Currentness, ticket, and D2 audit

The ticket retains the complete expected ToolDefinition, allowed permissions,
generation tuple, repository identity, composition identity, exact ToolCall,
current registry, capability-specific payload, and exact retained preparer.
Confirm consumes it, checks all bindings, revalidates the shared preparation,
then performs D2. Name-only Tool equality is insufficient.

Actual ordering in main.rs:3466-3676 is:

1. consume the single-use ticket;
2. check current composition, generations, repository, definition, and permissions;
3. check retained preparer identity;
4. revalidate shared preparation/review;
5. authorize_tool_dispatch (D2);
6. invalidate repository-bound reviewed Commit authorization;
7. emit HostExplicit Started;
8. run authorized_tool_dispatch against the current registry;
9. let repo.create-file perform one native create-new attempt.

Tickets are process-local, in-memory, capability-specific, five-minute TTL,
single-use, not persisted or resumed, and have no replacement/replay path.
Exactly-expired tickets fail. Wrong, duplicate, expired, stale, or activity-ID
Confirm fails; activity-ID Cancel fails. Cancel-before-start consumes the
ticket and returns the coordinator to Idle.
