# Task 080C: Host-Attested Certified Live Gates

Status: implemented pending deterministic and certified live validation.

## Decision

The opt-in Codex live examples treat final assistant text as diagnostic output,
not release-gate authority. A successful model statement does not prove that a
tool was invoked, that a host tool completed, or that the required repository
postconditions hold.

The host emits each human-readable marker only after all structural assertions
and child cleanup succeed:

- `RAH_ECHO_BRIDGE_OK` after one advertised `echo` request, entry, finish,
  expected input/output, continuation, `Completed`, and app-server cleanup.
- `RAH_REPOSITORY_OBSERVERS_LIVE_OK` after the four expected observer
  lifecycles, structured observer results, no mutation, `Completed`, and
  cleanup.
- `RAH_MULTI_PATCH_LIVE_OK` after the five-tool trusted composition, one
  canonical three-item `repo.patch` lifecycle and native mutation, observer and
  repository-invariant checks, `Completed`, and cleanup.

Consequently, exact marker text, a marker with surrounding prose, unrelated
benign prose, or an empty final response cannot alter a structurally valid
gate. Conversely, a marker claim cannot make a missing, duplicate, failed, or
incorrect tool lifecycle pass.

## Scope and security rationale

This is example/test/documentation harness work only. It does not change the
Generic Tool Bridge, `repo.patch`, permissions, trusted profiles, authority,
retry/deduplication semantics, or any RAH public API. The isolated `CODEX_HOME`
tooling remains mandatory because configuration drift and prose variability are
independent failure modes.
