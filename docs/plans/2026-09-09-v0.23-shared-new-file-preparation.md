## ADR relationship and API

ADR 0013 remains the sole underlying `repo.create-file` mutation authority.
ADR 0024 defines the future reviewed workflow around that Tool; Task 271 only
provides its reusable non-effectful preparation and revalidation foundation.
ADR 0021 remains the general HostExplicit boundary, while ADRs 0022 and 0023
remain precedent only. None of those ADRs were changed.

The public `rah-tools` API is:

```text
RepositoryCreateFilePreparationRequest { path: String, content: String }
RepositoryCreateFilePreparationError
RepositoryCreateFileReview
RepositoryCreateFilePreparation
RepositoryCreateFilePreparer
```

The request is closed to exactly `path` and `content`. The host reconstructs
the canonical existing ToolInput, exactly:

```json
{"path":"<validated logical path>","content":"<exact retained content>"}
```

No repository/native path, Git path, permission, ToolName, ToolInput,
authority, hash, parent identity, retry, Stage, or Commit input is accepted.

## Bounds and review

The shared creation admission preserves one target, 1--1024 UTF-8 path bytes,
0--262144 UTF-8 content bytes, NUL rejection, and a canonical serialized
request bound of 327680 bytes. Empty content is valid. Bytes remain exact:
there is no encoding conversion, BOM or newline conversion, normalization,
append, overwrite, or parent creation. The reviewed Windows route additionally
rejects components ending in `.` or space.

`RepositoryCreateFileReview` is deterministic, serializable, complete, and
bounded to 262144 bytes after safe deterministic escaping and required
metadata. It contains the operation, one-target fact, logical path and parent,
safe existing-parent and target absence facts, HEAD/index absence facts,
expected new untracked regular-file effect, complete escaped content, exact
byte length and SHA-256, BOM/newline/EOF/control/format facts, regular
non-executable intent, exclusive create-new/no-clobber semantics, and the
explicit non-effects and uncertainty warnings. Oversized complete review or
retained state fails as `ReviewTooLarge`; no preview or truncation is used.

`RepositoryCreateFilePreparation` is opaque and nonserializable as authority.
Its public getters expose only canonical ToolInput, complete review, review
identity, content hash, and content length. Its Debug output is redacted and
does not include content, native paths, ToolInput, or private identities. The
retained representation is checked against the 512 KiB process-local ceiling.

## Zero-effect and currentness design

Prepare and revalidate take the existing repository mutation lease only for a
single observation pass. They execute no Tool, native create, file or
directory creation, temporary file, worktree/index/HEAD/ref/history mutation,
Stage, Commit, model/runtime, MCP, Process Plugin, or durable authority
persistence. They perform only bounded Git observation, filesystem reads,
hashing, and identity inspection.

The policy shared by ordinary `RepositoryFileCreationTool` validation,
preparation, and revalidation captures host-owned repository root, `.git`, and
Git executable identities. Native parent traversal captures stable identities
for the root and every existing parent component, including the immediate
parent, while retaining the descriptor/handle-relative binding only during the
operation. Preparation retains those identities and protected HEAD, refs,
index, target HEAD/index, ignore, submodule, and sparse admission observations
privately. A different preparer identity, path/content/ToolInput, parent or
repository identity, Git executable identity, target state, or relevant Git
admission state is stale and fails closed.

Target absence now distinguishes `NotFound` (absent), successful metadata
(present), and every other metadata error (observation failure). Absence is
never inferred from an arbitrary I/O or permission error.

## Native attribution and result hardening

The native exclusive-create primitive captures the created object's stable
identity from the opened file descriptor/handle. That identity is retained on
write/sync failure and remains private. `ok` requires regular non-link/non-
reparse verification, exact bytes, unchanged protected Git state, and identity
equality between the observed target and this invocation's created object.
`write_failed_known` requires the same identity attribution plus a bounded
attributable prefix and valid protected state. Replacement or failed identity
observation is `uncertain`; partial files remain and are not cleaned up,
retried, replayed, restored, staged, or committed.

Windows `NtCreateFile` classification now maps only
`STATUS_OBJECT_NAME_COLLISION` to the collision class. Other native statuses
remain generic native-I/O failures. Any native create failure performs bounded
post-observation before `create_failed_known` is returned; an error category
alone is insufficient, and ambiguous state is `uncertain`. The public Tool
name, Execute permission, closed `{path, content}` schema, and exact six result
classes remain unchanged:

```text
ok, invalid_target, precondition_failed, create_failed_known,
write_failed_known, uncertain
```
