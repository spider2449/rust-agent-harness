### Task 303 correction gate

The correction is independently confirmed closed. Ordinary destination Git
absence now checks HEAD and the index separately. On Windows, index discovery
uses bounded `--icase-pathspecs`; HEAD discovery walks only the relevant tree
levels and follows the actual returned tree spelling component by component.
Both are narrowing observations only: strict parsing and host-owned,
component-wise `paths_equivalent` comparison decide collision authority.

The implementation and tests cover:

- HEAD and index case-equivalent collisions, including a tracked-but-missing
  HEAD entry;
- all index stages, intent-to-add, and unmerged/conflict forms;
- supported tree/blob/gitlink record shapes and malformed/ambiguous records;
- absent worktree entries, nested destination depths, and case-sensitive
  non-Windows behavior; and
- bounded HostExecutionPolicy observation with timeout, overflow, failure, and
  malformed output failing closed.

Collision rejection occurs before revalidation completes and before the native
rename counter/primitive. The critical result is `precondition_failed`, with
zero native attempts and no effect. The worktree entry is not required for Git
collision detection.

### Desktop, frontend, Tauri, and privacy
