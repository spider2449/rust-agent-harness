## Evidence required before selecting a capability

Observe a human completing a real repository question or bounded authoring
workflow with their existing local provider, at their usual window size and a
narrow window if relevant. Record goal, configuration, concrete steps,
completion, confusion/errors and any workaround. Include multiple Tool calls,
inspection of Activity and Status/Review, and return to Chat; preserve the
distinction between model requests and manual Host actions. Use a disposable
repository for mutations and existing host review/authorization contracts.

Determine whether the user can identify which Tool operation belongs to the
current turn, distinguish running/completed/failed or uncertain outcomes, and
return to Send/Cancel without an unintended action. Record whether confusion
changes an outcome or repeatedly interrupts work. Existing panel toggles and
navigation are the comparison, not an assumed failure. Do not manufacture a
failure or infer a capability gap from an absent UI convenience.

If demonstrated friction warrants work, first assess a bounded presentation
change using existing host events and controls. Select implementation only when
the concrete failed/impeded goal, smallest remedy and deterministic plus actual
Desktop acceptance contract are supported. Otherwise continue usage. This is
the next evidence activity, not an authorized implementation task.
