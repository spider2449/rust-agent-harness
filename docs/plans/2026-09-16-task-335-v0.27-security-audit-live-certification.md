## Windows live certification evidence

The ignored test
`task_335_windows_host_driven_remembered_workspace_live_certification` ran
with `RAH_RUN_V027_REMEMBERED_WORKSPACE_LIVE=1` at the exact source SHA. It
created a fresh bounded app-data root, repositories A and B, a separate
invalidated repository C, and unrelated sentinel files. Native Git was used
for repository setup and integrity observation.

### P1, P2, and P3

- P1 began with an empty catalog, zero membership, and no active repository.
- P1 remembered A and B, confirmed generic catalog presentation contained IDs,
  labels, and hint presence but not the raw sentinel path, explicitly revealed
  A, hid it, reordered the catalog, admitted A, and confirmed admission did not
  activate it.
- P1 then explicitly activated A and closed cleanly.
- P2 showed A/B and their order, but zero membership, no active repository,
  no composition, commit/index/workflow state, HostExplicit preparation,
  provider activation, runtime connection, or executable conversation binding.
- P2 admitted A, obtained a new `RepositoryMemberId` different from P1, and
  confirmed no activation. It explicitly activated A.
- P2 admitted B while A was active; A remained active. Explicit activation of
  B then performed the switch.
- With B active, deleting B from the remembered catalog removed durable B but
  left B's process-local membership, active repository, composition, and
  repository files intact.
- P3 showed deleted B absent, retained A present, and zero membership/active
  repository after restart.

### Invalid current facts and malformed catalogs

- C remained descriptively visible after its `.git` was removed while stopped.
  Explicit admission failed through current repository validation, with no
  membership or activation effect.
- A malformed/truncated catalog left bytes unchanged, produced unavailable
  remembered state, and created no partial candidates or authority.
- A valid-looking `version: 2` catalog produced unsupported/unavailable state,
  left bytes unchanged, and performed no migration, downgrade, or authority
  restoration.

### Privacy, repository, and process accounting

The sentinel component `RAH_V027_PRIVATE_PATH_SENTINEL` was searched across
generic catalog JSON, application status, effective authority, activity,
transcript, and error/presentation output. It occurred only in the durable
catalog and explicit reveal/admission host handling; it did not occur in the
generic or model-facing surfaces. The HTML-like label was rendered as text.

The missing-candidate startup seam recorded zero candidate path accesses.
Before/after A and B snapshots showed unchanged HEAD/ref, index, worktree
sentinels, and `.git` form for descriptive operations and admission. Activation
changed only process-local RAH state.

Observed counts were:

```text

MCP provider activations = 0
Process Plugin activations = 0
automatic commits = 0
network Git = 0
```

The certification-owned test process and native Git children were reaped. No
Codex or provider child was started by certification. The isolated app-data
and repository roots were removed by bounded fixture cleanup; no development
repository or broad process-name termination was used.

## Explicit nonclaims

- GUI automation was not used; this is host-driven production-backend
  certification.
- A real junction/reparse ancestor was not created by the final live fixture.
  Deterministic `remembered_workspace` reparse tests passed, including proof
  that rejection leaves catalog and coordination state unchanged.
- A true two-process simultaneous mutation run was not executed. Deterministic
  coordination serialization and bounded failure tests passed; no claim is
  made about an additional live simultaneous-process observation.
- Model-selected dynamic Tool dispatch remains unestablished:

  `MODEL-SELECTED DYNAMIC TOOL DISPATCH NOT ESTABLISHED UNDER THE APPROVED GPT-5.6-TERRA LIVE GATE.`

- This gate does not claim network isolation, race-free TOCTOU protection, or
  automatic recovery/replay after uncertain native effects.
