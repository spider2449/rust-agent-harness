## Ticket and currentness contract

The ticket is RAH-generated, opaque, capability-specific, process-local,
in-memory, single-use, nonpersistent, and nonresumable. It retains the exact
preparer and private preparation. Expiry is exact: elapsed < 300 seconds is
valid and elapsed >= 300 seconds is expired, implemented at
host_invocation.rs:22-24 and 275-278. No automatic replacement ticket or
reprepare exists.

Ticket and activity IDs are independently generated and distinct. Activity IDs
cannot Confirm or Cancel. Wrong, expired, duplicate, stale, and activity-ID
tickets are rejected without Tool execution. Evidence is
host_invocation.rs:874-879, 1122-1222; main.rs:15286-15447; and the Task 285
live record.

The retained preparation binds logical path, bytes/hash/length, mode, target
and parent identities, link count, repository/Git/.git identities,
HEAD/tree/blob/branch, stage-0 and raw index, refs, supported state, review
identity, canonical ToolInput, exact ToolDefinition and permission membership,
preparer identity, composition/registry identity, and generation tuple.

Bytes/hash/length equality alone is insufficient. The same-byte target
replacement test at main.rs:15450-15535 is rejected because FileIdentity

## Independent reviewed post-attempt proof

HostExplicit does not trust Tool status alone. It first applies the strict
output parser, then independently proves the permitted terminal class.

known_no_effect requires the same preparer and repository resources, exact
target FileIdentity, link count, bytes/hash/length, parent binding,
HEAD/blob/index relationship, raw index, and protected Git state.
Same-byte replacement is downgraded to uncertain.

deleted_verified requires the same retained resources, retained parent identity,
specifically confirmed NotFound for the target, no same-name or Windows
case-equivalent replacement, unchanged index, unchanged HEAD/tree/blob/branch/
refs and Git resources, and no contradictory observation. Generic metadata or
access failure is not absence. Parent replacement is downgraded to uncertain.
The coupling test at main.rs:15629-15784 covers confirmed absence, visible
target, intact known-no-effect, same-byte recreation, and parent replacement.

## Windows semantics

The Windows contract is one native DeleteFileW attempt followed by one
immediate proof pass. There is no polling, sleep/recheck loop, second delete,
retry, replay, cleanup, or recovery. A successful DeleteFileW return is the
filesystem effect commit point, not by itself proof of absence.

Delete-pending visibility, same-name or case-equivalent replacement, reparse
replacement, and access/sharing/I/O observation failure remain uncertain unless
independently proven otherwise. No race-free TOCTOU claim is made.

Deterministic Task 283 evidence establishes failure/proof/currentness rules.
Task 285 separately certifies the connected-current Windows success path. It
does not reproduce every failure mode live.
