## Milestone summary

The release capability is **HostExplicit Reviewed New-File Authoring** through
the existing `repo.create-file` Tool:

```text
typed human {path, content}
 -> zero-effect shared Prepare
 -> complete bounded backend-derived review
 -> opaque single-use ticket
 -> ticket-only Confirm
 -> connected-current / exact-definition / permission / preparer checks
 -> shared creation revalidation
 -> D2
 -> reviewed Commit authorization invalidation
 -> HostExplicit Started
 -> authorized_tool_dispatch
 -> current ToolRegistry
 -> existing repo.create-file
 -> ADR 0013 RepositoryFileCreationPolicy
 -> strict result classification
 -> descriptive repository refresh
```

The closed Prepare request is exactly `{path: String, content: String}`;
unknown fields fail closed. The bounds are one file, path 1..=1024 UTF-8
bytes, content 0..=262144 UTF-8 bytes, NUL rejected, canonical request at most
327680 bytes, and complete serialized review at most 262144 bytes. Empty
content is allowed and content is exact without BOM/newline conversion,
normalization, templating, append, overwrite, or an automatic final newline.
Complete review is required; if it cannot fit, preparation fails before a
ticket exists.

The existing parent must be safe and identity-verified. The target must be
absent from the worktree, HEAD, and all index stages including intent-to-add.
Ignored targets, submodules, unsupported sparse-checkout, Windows
reserved/device/ADS/UNC/verbatim forms, reviewed trailing-dot/space components,
and symlink/junction/reparse traversal fail closed. No parent directory is
created. Exclusive acquisition is the commit point (`O_CREAT | O_EXCL` intent
on Unix; `CREATE_NEW` / `FILE_CREATE` intent on Windows). Complete writing is
not an atomic all-or-nothing transaction.

The exact nine eligible Tools are:

```text
fs.read
repo.file-info
repo.status
repo.diff
repo.diff-staged
repo.create-branch
repo.patch
repo.edit-files
repo.create-file
```

`repo.delete-file`, `repo.rename-file`, `repo.create-directory`, `repo.commit`,
MCP Tools, Process Plugin Tools, fixture Tools, and unknown Tools remain
ineligible. There is no wildcard/category/provider route.

## Ticket, privacy, result, and Git semantics

Prepare has zero Tool/native/repository/index/HEAD/ref/history/Stage/Commit or
durable-authority effects. Confirm and Cancel receive ticket ID only. The
ticket is opaque, process-local, in-memory, capability-specific, single-use,
exact-preparation/currentness-bound, and valid for an inclusive five-minute
TTL. It is not persistent or resumable and has no replacement path.

Generic activity uses a distinct non-authority activity ID with
`ticket_id != activity_id`; it is not derived from the ticket and cannot
Confirm or Cancel. Generic activity, persistence, and logging exclude the
ticket, complete content/source sentinel, complete source-bearing review, raw
ToolInput/ToolOutput, native paths/parent identities, and private object
identities. A successful generic terminal result is status-only.

The exact six ADR 0013 statuses are `ok`, `invalid_target`,
`precondition_failed`, `create_failed_known`, `write_failed_known`, and
`uncertain`. Known no-effect requires proof; `write_failed_known` may retain
an attributable empty or partial file; `uncertain` preserves unknown state.
There is no retry, replay, delete, rollback, restore, compensation, Stage, or
Commit. Effectful creation invalidates stale repository-bound reviewed Commit
authorization, and refresh is descriptive only. A successful create is one
new untracked worktree file, not an index, HEAD, ref, history, Stage, or Commit
change.
