## Prepare observations and blocking failure

The final live attempt reached production Prepare and received a nonempty
opaque ticket response plus the production prepared HostExplicit event.
Before any Confirm, the evidence test inspected the serialized event and
stopped with:

Prepare activity was not redacted

The production command currently emits the Prepare event with
invocation_id: ticket_id. Consequently, the serialized event contains the
same opaque ticket identifier that was returned to the caller. This violates
the required Task 263 privacy condition. The event also remains a generic
activity surface rather than the source-bearing review surface.

Because this required observation failed, the test deliberately did not
continue to its post-Prepare zero-effect assertions or any Confirm. Therefore
the following are not certified by this task:

- live Prepare Tool/native counts;
- live complete review assertions;
- Confirm, Started, D2-to-dispatch completion, or terminal ok;
- four-target native attempt counts;
- actual post-effect hashes/lengths;
- repository refresh after a successful effect; and
- consumed-ticket duplicate rejection after a successful effect.

The fixture was still pre-effect when the test stopped. No Tool execution,
native replacement, Stage, Unstage, Commit, model turn, prompt, or provider
process was initiated by the failed certification window.

activity correlation. `PreparedHostInvocation` now retains a process-local

terminal, and Cancel activity use that non-authority ID. Confirm and Cancel
still accept only the actual ticket in the exact `{ "ticketId": "..." }`
request shape. The activity ID is rejected as both Confirm and Cancel input.

`RAH_SECRET_AUTHORITY_TICKET_SENTINEL` and serialize Prepared activity for
