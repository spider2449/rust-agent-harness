## Released behavior and authority record

The release theme remains **Linked Git Worktree Repository Support**. RAH
Desktop can admit supported ordinary and linked Git worktrees as distinct
repository members even when they share one Git common directory. Exactly one
member remains active. Effects remain bound to the selected worktree identity
and capability-specific Git currentness.

The historical authority classification is **NARROW EXTENSION**, not
NEW AUTHORITY CATEGORY. ADR 0027 and ADR 0028 remain authoritative, ADR
0029 remains Accepted, and linked support is a repository-identity extension.
HostExplicit remains exactly 11. There is no new PermissionLevel, worktree
mutation authority, Stage/Unstage authority, Commit authority, or generic
Git/process/filesystem authority.

The core identity boundaries remain:

    same common Git directory != same repository member
    shared common Git state != sibling executable authority

There is no union ToolRegistry and no sibling selector in ordinary Tool input.
The supported linked form remains the complete validated relationship of the
selected worktree root, bounded gitfile, private worktree Git directory,
standard commondir relationship, common Git directory, backlink, exactly
matching native Git worktree registration, filesystem identity, fixed Git
semantic agreement, and Git executable identity. Native absolute and
supported relative link records remain supported; arbitrary Git-recognized,
copied, fabricated, or malformed gitfiles do not become supported.

Rejected layouts remain submodules, --separate-git-dir, bare repositories,
stale/prunable registrations, unsupported nested repository relationships,
and unsupported symlink/reparse-mediated identities.

Stage/Unstage isolation remains selected-index-only: Stage A changes only A's
index and Unstage A changes only A's index; the certified main/B behavior
preserves B's staged state. Reviewed Commit remains ADR 0016 authority,
bound to selected identity, selected index, selected HEAD, attached branch,
expected selected branch OID, and existing review/currentness. Shared object
store creation is normal Git Commit behavior, not sibling authority. Detached
linked observation may work, but reviewed Commit remains attached-branch-only.

Currentness remains operation-specific. An unrelated B Commit on another
branch does not stale an A review when A's HEAD, index, and selected branch
OID are unchanged. Movement of A's selected branch ref makes the old review
stale, yields zero native Commit spawn, and does not retry or rebind. Local
branch creation uses selected HEAD, creates one intended local ref, does not
checkout/switch, and does not create a worktree.

RAH recognizes existing valid worktree identity only. It does not provide
authority for git worktree add, remove, prune, repair, move, lock, or unlock.
Close and inactive-member removal remain RAH membership/authority operations,
not Git worktree lifecycle operations.
