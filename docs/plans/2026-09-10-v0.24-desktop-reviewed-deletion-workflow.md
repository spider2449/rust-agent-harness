## Accepted separation and frontend boundary

The workflow preserves the following separation:

```text
ADR 0017 = sole deletion mutation authority
ADR 0021 = generic HostExplicit currentness, D2, ticket, and dispatch boundary
ADR 0025 = reviewed human deletion workflow boundary
Task 283 = backend eligibility, Prepare/Confirm, proof, and classification
Task 284 = typed human input, direct review presentation, and ticket-only UI
```

The frontend is presentation and an untrusted requester. It does not infer
permission, eligibility, currentness, deletion authority, target identity,
expected SHA or length, HEAD/index state, proof, result classification, or D2.
Eligibility is rendered only when backend metadata reports
`hostInvocation.eligible === true` and exact kind `repo_delete_file`. No
frontend allowlist or provider/model admission rule is added.

## Typed deletion workflow

The exact deletion form accepts only the human field `path`, presented as a
required repository-relative text input with a 1024-character UX limit. The
submit action is `Prepare`, and it sends exactly:

```javascript
const request = {
  path: form.querySelector('[data-host-input="path"]').value,
};
const prepared = await invoke("host_prepare_repo_delete_file", { request });
```

The frontend performs no local filesystem, Git, native-path, precondition, or
hash work. The 1024-character bound is UX-only; backend UTF-8, NUL, target,
and reviewed-content bounds remain authoritative.

The form explains that exactly one existing tracked file is removed, Prepare
does nothing, the backend supplies the complete exact preimage before Confirm,
the result is an unstaged worktree deletion, and there is no Trash/Recycle
Bin guarantee, backup, restore, automatic Stage, or automatic Commit.

## Complete direct review

The `delete_file` review branch presents all backend-derived mutation-relevant
fields without recomputation:

```text
operation, target_count, path, tracked_state, file_mode, file_intent,
preimage_encoding, content_byte_length, content_sha256, bom,
head_blob_relationship, index_relationship, expected_effect,
post_delete_git_meaning, content_facts, non_effects, warnings
```

The complete escaped preimage is displayed in a dedicated `<pre>` using
`textContent`. It is not truncated, collapsed, replaced by a digest, or
inserted as HTML. Content facts include carriage returns, line feeds, CRLF
pairs, final newline/EOF state, tabs, trailing spaces, control and format
escapes, counts, and empty state. Backend `non_effects` and every backend
warning are rendered as safe text, including permanence, lack of Trash,
backup, restore, rollback, retry/replay, and manual-inspection guidance.

## Ticket, activity, and results

The existing active in-memory review dialog remains the only place holding the
direct review and opaque ticket. Confirm and Cancel continue to send exactly
`{ request: { ticketId: active.ticketId } }`; activity IDs, paths, source,
hashes, review objects, Tool input, permissions, and authority state are not
sent. Closing the dialog uses the existing Cancel-before-start behavior.

Deletion result labels are exactly:

```text
deleted_verified    = Verified — reviewed file deleted
known_no_effect     = Delete failed — reviewed file proven unchanged
invalid_input       = Rejected — invalid deletion input; no deletion effect
precondition_failed = Rejected — deletion precondition failed; no deletion effect
uncertain           = Uncertain — final file state cannot be proven
```

Terminal explanations preserve backend semantics. `known_no_effect` states
that the backend proved the exact reviewed file remains intact, rather than
describing only a generic Tool error. `uncertain` requires manual inspection
and explicitly provides no automatic retry. HostActivity retains
`Host action — not Model` and deletion-specific distinctions for completed,
known-no-effect error, stale rejection, cancellation, and possible effect
unknown states.

## Privacy and hostile-content safety

The complete source-bearing review remains ephemeral direct-review data only.
It is not copied to HostActivity, transcript, conversation persistence,
localStorage, sessionStorage, preferences, URLs, dataset attributes, hidden
fields, logs, error text, or telemetry. Terminal cleanup uses the existing
active-review cleanup mechanism, and the ticket is never persisted or
resumed.

Deterministic frontend assertions cover hostile source values including HTML
tags, event-handler markup, ampersands, quotes, JSON-looking text, bidi and
zero-width characters, NUL/control values, and escaped representations. The
tests require text APIs and reject `innerHTML`, `insertAdjacentHTML`, and
other HTML insertion paths.
