## Backend contract

The production HostExplicit set is exactly these ten names:

```text
fs.read
repo.file-info
repo.status
repo.diff
repo.diff-staged
repo.create-branch
repo.patch
repo.edit-files
repo.create-file
repo.delete-file
```

Deletion is admitted only for a selected repository with host-granted
`RepositoryFileDeletionAuthority`, an exact current `repo.delete-file` Tool,
and a successfully constructed retained `RepositoryDeleteFilePreparer`.
Provider metadata, Execute permission, Tool presence alone, prefixes, and
categories do not create eligibility. Rename, directory creation, Commit,
providers, fixtures, and unknown Tools remain ineligible.

The backend request is the closed typed `{path}` DTO. Prepare reconstructs the
unchanged three-field ordinary Tool input from the preparer and returns the
complete `RepositoryDeleteFileReview` only in the direct
`PreparedDeleteFileResponse`. Generic Prepared and Started activity carries a
distinct non-authority activity ID, no ticket, no review, and no raw Tool
payload. Prepare is zero-effect and issues no ticket on any bounded failure.

The retained ticket payload owns the shared preparation and the exact retained
preparer. Confirm consumes the ticket, verifies generations, composition and
repository identity, exact ToolDefinition and permission membership, retained
preparer identity, and shared deletion revalidation before D2. Only after D2
does it invalidate reviewed repository-bound Commit authorization, emit
HostExplicit Started, and dispatch through the current
`authorized_tool_dispatch -> ToolRegistry -> repo.delete-file` path. Cancel,
Prepare, and all pre-Started rejection paths preserve Commit authorization.

## Independent deletion classification

The shared preparer now exposes reviewed-only non-mutating proof methods. The
known-no-effect proof requires the same preparer/resource identity, exact
target FileIdentity and link count, source bytes/hash/length, parent binding,
HEAD/blob/index relationship, raw index, and protected Git fingerprint.
Same-byte replacement with a different FileIdentity fails this proof.

The deleted-verified proof requires the same resource/preparer binding, a
protected root and exact retained parent identity, specifically confirmed
`NotFound` target absence, no same-name or case-equivalent entry, unchanged
raw index, and unchanged protected HEAD/tree/blob/branch/refs state. A generic
metadata failure, visible delete-pending path, replacement, or contradictory
observation is uncertain. The reviewed route performs one native Tool attempt
and one immediate proof pass: no polling, second delete, retry, cleanup,
restore, replay, or rollback.

The Desktop parser accepts only the ordinary five statuses with their exact
key/type/path/error shapes. It combines structural output with independent
proof and maps proof-insufficient or malformed results to status-only
`uncertain` and `possible_effect_unknown`. Valid terminal results are
status-only in generic activity. Descriptive refresh runs only for effect or
possible-effect outcomes and never upgrades uncertainty or recreates
authority.
