## Release theme and authority

Release theme: **Linked Git Worktree Repository Support**.

RAH Desktop can explicitly admit ordinary and supported linked Git worktrees as
distinct repository members even when they share one Git common directory.
Exactly one member remains active, and all repository effects stay bound to the
selected worktree identity and capability-specific Git state.

Authority classification: **NARROW EXTENSION**, not `NEW AUTHORITY CATEGORY`.
ADR 0027 remains authoritative. ADR 0029 is Accepted and adds one closed
linked-worktree identity form. ADR 0028 restart/persistence rules and existing
mutation/Commit ADRs remain authoritative. No ADR amendment is required.
HostExplicit remains exactly 11. No new permission, mutation authority, Tool,
generic Git/filesystem authority, provider authority, model routing authority,
or persistence/schema authority was introduced.

## Evidence and claims

Supported forms are ordinary main worktrees and closed validated linked
worktrees with private Git state, a standard common-directory relation,
backlink, and exactly one matching native registration. Absolute and supported
relative link records are accepted only when filesystem and fixed read-only Git
semantic evidence agrees. Same common Git directory is not duplicate identity
and does not merge authority.

The one-active rule, selected-root observation, selected-index Stage/Unstage,
selected-worktree content authoring, reviewed selected-branch Commit, detached
observation/read, and selected-HEAD branch creation remain capability-specific.
An unrelated sibling Commit does not globally stale the selected review;
selected-ref movement does stale it and prevents native spawn, retry, or
rebinding. External move/removal or linked metadata mutation makes retained
identity stale and requires fresh explicit admission.

RAH does not create, remove, prune, repair, move, lock, or unlock worktrees.
Arbitrary/copied/malformed gitfiles, stale/prunable registrations, submodules,
`--separate-git-dir`, bare repositories, unsupported nested relationships, and
unsupported symlink/reparse-mediated identity remain rejected.
