# Task 374 — RAH v0.32 Scope and Authority Roadmap

Date: 2026-09-20
Status: **RECOMMENDATION — READY FOR TASK 375 CONTRACT RESEARCH**
Task type: research and product scope only

This document selects the v0.32 product scope. It does not implement the
capability, change production behavior, change an authority contract, create an
ADR, change dependencies, bump versions, or authorize release work.

## Decision

The sole v0.32 primary capability is:

**Bounded Repository Structure Listing / Browse**

The capability answers bounded structural questions about the host-selected
active repository, such as:

\`\`\`text
What tracked entries are directly under the repository root?
What is under crates/?
What files and directories are under crates/rah-tools/src/?
Where should I search next?
\`\`\`

The intended unfamiliar-repository workflow becomes:

\`\`\`text
select repository
  -> bounded tracked structure browse
  -> repo.search for a known concept or literal
  -> fs.read for a known file
  -> existing author/review Tools
\`\`\`

Structure browsing complements v0.31 \`repo.search\`; it does not replace,
redesign, or broaden that closed \`path|text\` search contract. The product gap
is structural navigation when the agent has no matching query yet.

The preferred initial product semantics are one bounded directory level per
call, using a fixed tracked Git inventory and host-side projection. Task 375
must freeze the canonical Tool name, request/output schema, exact caps, and
boundary behavior before implementation begins.

\`\`\`text

## Authority classification

The selected capability is a **NARROW EXTENSION**.

Its expected effective authority is:

\`\`\`text
EffectClass       = ReadOnly
AuthorityCategory = RepositoryObservation
PermissionLevel   = Execute
repository_bound  = true
\`\`\`

This is not \`NONE\` because the Tool deliberately enumerates tracked logical
path names without requiring a matching query. It therefore broadens bounded
observation and disclosure convenience inside the selected repository
boundary.

It is not a new authority category because the namespace is already within the
selected repository observation boundary established by v0.31. The capability
does not grant mutation, network, credential, persistence, Git ref/index/history,
generic process, generic filesystem, cross-worktree, or cross-repository
authority. No new \`PermissionLevel\` is expected.

The \`Execute\` value remains the existing outer permission gate for a fixed,
host-owned read-only observer operation. It must not be interpreted as generic
process or generic Git authority.

No new ADR is expected. If Task 375 discovers that the capability needs a new
authority category, persistent/background indexing, an external search
executable, model-selected Git syntax, cross-worktree selection, network
access, or another authority outside this classification, implementation must
stop and authority research must reopen before any Rust change.

## Preferred security and inventory model

The starting security model for Task 375 is:

\`\`\`text
fixed tracked Git inventory
  -> validate selected repository boundary
  -> host-side path projection
  -> deterministic direct-child structure result
\`\`\`

Git is an inventory source only. The model must never control the Git
executable, argv, pathspec syntax, cwd, environment, timeout, or result cap.
The host must supply the selected active repository and its validated Git
identity through the existing repository observer composition.

The default disclosure policy is **tracked paths only**. Native filesystem
directory enumeration is not the default because it would naturally expose
untracked names and would require a separate privacy/ignore contract. A
directory node may be synthesized from tracked path components; it is not
evidence that arbitrary filesystem directory enumeration occurred.

The first version should be direct children only. A bounded optional depth
greater than one is a Task 375 research question, not a Task 374 schema
decision. Arbitrary recursive tree dumps are outside the preferred scope.

The capability must not include file contents. A minimal candidate entry is:

\`\`\`text
path = repository-relative logical path
kind = file | directory
\`\`\`

The candidate output must not include absolute paths, filesystem IDs, mtime,
ctime, owner, ACL, Git object IDs, private Git directories, common Git
directories, registration data, authority generations, executable paths,
profile paths, cwd, environment, raw stderr, or browsing history.

\`\`\`

\`\`\`text

\`\`\`

## Linked-worktree and boundary implications

The capability inherits ADR 0027 and ADR 0029. If linked A is active:

\`\`\`text
browse A -> A's tracked structure only
\`\`\`

The result must not reveal main-only paths, linked-B-only paths, private A or
private B Git directories, common Git storage, worktree registration, shared
object-store paths, or any other sibling/private metadata. There must be no
Tool input field named \`repository\`, \`member\`, \`worktree\`, \`root\`, or
\`gitdir\`.

The contract must preserve the existing fail-closed nested repository boundary
policy. Task 375 must explicitly determine behavior for nested \`.git\`
boundaries, submodules, symlink files, directory symlinks, Windows junctions
and reparse points, sparse-checkout omissions, deleted tracked paths, case
aliases, and invalid UTF-8 Git paths. It must not turn structural browsing into
an easier path around v0.31 boundary enforcement.

The likely safe baseline is to admit only tracked paths that are valid logical
repository-relative UTF-8 paths and whose current selected-worktree objects
remain eligible under the existing repository boundary policy. Structural
directories can be derived from those paths. The exact treatment of absent
tracked paths, sparse omissions, gitlinks/submodules, and invalid names belongs
to Task 375.

## Currentness and deterministic bounds

The result must remain \`best_effort\`. The contract must not claim a filesystem
snapshot, transaction, race-free TOCTOU proof, or global Git lock. No
uncertain observation is automatically retried or replayed.

Task 375 should define identity revalidation points, fixed Git executable
identity checks, repository lease use, disappearance or type-change handling,
and the rule for omitted absent tracked paths. Structural failures must fail
closed rather than return misleading partial structure.

The following are research candidates for concrete caps, informed by existing
observer precedents; they are not frozen by Task 374:

\`\`\`text
request bytes             <= 4 KiB
logical directory/path    <= 1024 UTF-8 bytes
tracked inventory         <= 4 MiB
inventory records         <= 100,000
returned entries          <= 128
normalized output         <= 128 KiB
total observation time    <= 15 s
\`\`\`

The final contract must provide deterministic lexical sorting, deterministic
truncation, \`complete=true|false\`, an explicit truncation reason, and no
silent inventory truncation. An inventory limit or malformed fixed inventory
must be distinguished from a normal result cap. The output must expose only
safe logical paths, structural kind, completion/truncation state, and bounded
omission accounting where it is necessary to interpret the result.

## HostExplicit, profile, and bridge decisions

The browse capability is an ordinary model Tool routed through the existing
Generic Tool Bridge:

\`\`\`text
active repository composition
  -> ToolRegistry
  -> Generic Tool Bridge
  -> bounded structure Tool
  -> fixed tracked inventory
  -> host-side projection
  -> ToolOutput
  -> model continuation
\`\`\`

The bridge remains the authorization and dispatch boundary. Model input cannot
select the repository, worktree, Git executable, argv, cwd, environment,
timeout, result cap, or inventory policy.

HostExplicit remains exactly 11. The new Tool is not added to the HostExplicit
\`host_kind\` allowlist, and \`repo.create-directory\` is not added while this
milestone is being scoped. Trusted Profile composition may expose the existing
read-only repository observation authority according to its current host-owned
rules, but provider metadata cannot create or escalate it.

## Privacy and disclosure rules

The minimum model-visible result needed for navigation is:

\`\`\`text
repository-relative logical path
file/directory structural kind
completion and truncation state
bounded omission accounting if required
\`\`\`

The capability must not disclose absolute repository roots, private/common Git
directories, linked-worktree registration paths, filesystem IDs, Git executable
paths, profile paths, cwd, environment, raw stderr, generations,
\`RepositoryMemberId\`, ToolRegistry handles, or a persistent browse index. No
browsing history is persisted. Restart semantics remain zero executable
repository authority.

Untracked discovery remains deferred. Task 366 intentionally selected
tracked-only behavior because the hardened observer environment disables
ambient system/global Git configuration, making user-global ignore semantics
unsuitable as an implicit privacy boundary. v0.32 must not use structure
browse as a backdoor for untracked or ignored-file discovery.

## Explicit v0.32 non-goals

Unless Task 375 finds an unavoidable contradiction, v0.32 does not add:

- a new \`PermissionLevel\` or authority category;
- a generic filesystem listing or arbitrary recursive filesystem walk;
- untracked or ignored discovery;
- regex, fuzzy, semantic, or vector search;
- a background or persistent repository index;
- generic shell, process, or Git execution;
- network Git, network MCP, credentials, or OAuth;
- Git worktree add/remove/move/prune/repair/lock/unlock lifecycle;
- multiple active repositories, cross-worktree selectors, or a union registry;
- persistent executable repository authority;
- automatic Trusted Profile hot reload;
- HostExplicit #12;
- Codex baseline upgrade or recertification as part of product scope;
- version bump, tag, release, publication, or cleanup work.

## Deterministic evidence expectations

The eventual implementation and audit sequence must test real production paths
with deterministic barriers and no sleeps. At minimum it must cover:

| Case | Expected evidence |
| --- | --- |
| Root and nested valid directories | Stable direct-child file/directory results with lexical order. |
| Empty or unknown directory | Defined bounded empty result or fail-closed validation result. |
| Result and inventory saturation | Deterministic truncation, explicit reason, complete flag, and no silent inventory loss. |
| Tracked versus untracked/ignored | Only the selected tracked policy is visible; untracked-only and ignored-only names remain absent. |
| Tracked file matching ignore rules | It remains eligible because it is tracked, subject to the final currentness/boundary contract. |
| Deleted or sparse-omitted tracked path | Defined omission or structural failure; no misleading claim that the current object exists. |
| Nested repository and \`.git\` | Boundary is rejected or omitted according to the closed contract; no child repository disclosure. |
| Symlink, directory symlink, junction, and reparse | No traversal or target disclosure. |
| Case aliases and invalid/special paths | Host path validation remains deterministic and fail-closed. |
| Submodule/gitlink and binary files | No unintended child-repository or content disclosure. |
| Identity/currentness race, cancellation, timeout | Conservative bounded completion/failure, no retry or replay. |
| Output/privacy sentinels | No absolute/private Git paths, executable/profile paths, raw stderr, IDs, or authority generations. |
| Bridge/profile route | Tool is present only in the active selected registry and remains observation authority. |

The later Windows certification must use a disposable fixture containing:

\`\`\`text
main
linked A
linked B
\`\`\`

Active A must contain deterministic tracked structure such as:

\`\`\`text
src/
src/lib.rs
src/module/
src/module/a.rs
docs/
docs/guide.md
\`\`\`

The fixture must also include an untracked-only directory, an ignored
directory, a tracked file matching an ignore rule, a nested repository, a
junction/reparse target, a binary file, and invalid/special path cases where
the platform permits them. The gate must prove:

\`\`\`text
browse root -> tracked A structure only
browse src  -> deterministic direct children
main/B sentinels -> absent
untracked/ignored-only names -> absent
private/common Git metadata -> absent
\`\`\`

There must be no intentional repository mutation. Evidence must remain
host-driven production-path evidence and must not claim GUI automation,
model-selected dynamic Tool dispatch, Linux/macOS parity, race-free TOCTOU,
network isolation, rollback, compensation, or OS sandboxing unless separately
proven.

The v0.31 Codex history remains unchanged: \`codex-cli 0.149.0\` was
unavailable during Task 369, so real model-selected \`repo.search\` inference
under that baseline was not certified. Task 374 neither rewrites that
nonclaim nor couples structure browsing to an opportunistic Codex upgrade.

## Stop conditions

Task 375 and any later implementation must stop and report a scope or authority
conflict if any of the following becomes necessary:

- native enumeration that discloses untracked or ignored names without an
  explicit privacy/ignore contract;
- a model-controlled repository, worktree, root, Git executable, argv, cwd,
  environment, timeout, or result-cap selector;
- access to sibling worktrees, common/private Git metadata, object storage,
  history, or another repository;
- a new mutation, network, credential, persistence, process, or Git lifecycle
  authority;
- background/persistent indexing or a new cache outside the selected bounded
  observation;
- weakening nested repository, symlink, junction, reparse, or linked-worktree
  boundaries;
- a need to add HostExplicit #12 or change the one-active architecture;
- a requirement for a new ADR or dependency that is not justified by contrary
  evidence;
- inability to provide deterministic bounds, fail-closed structural failures,
  currentness treatment, safe privacy output, and the stated Windows fixture;
- evidence that the winning capability is not the highest-leverage remaining
  v0.31 product gap.
