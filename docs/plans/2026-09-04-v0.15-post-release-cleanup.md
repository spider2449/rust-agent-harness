## Preserved v0.15 historical scope

The release remains the bounded, host-owned `repo.create-directory`
capability. It permits exactly one new ordinary directory leaf at an explicit
repository-relative path, with an existing validated parent and absent
destination. It does not provide recursive creation, `mkdir -p`, placeholders
or `.gitkeep`, Git mutation, staging, commit, retry/replay, rollback, or
compensation. Directory creation remains separate from repository read,
content mutation, file creation/deletion/rename, index mutation,
reviewed-commit/history mutation, and Execute. Model requests, provider
metadata, Trusted Profile composition, and frontend state are not authority.

Windows live certification is PASS. Windows and Ubuntu/Linux deterministic
validation remains evidence-level only where established; Linux live
certification is not established. A successful empty-directory creation may
leave `git status --short` empty because Git does not track empty directories;
the filesystem postcondition proves creation, and v0.15 creates no placeholder
merely to produce Git visibility.
