## Contract

Task 215 integrates four host-only actions: Choose Profile, Restore, Forget,
and Clear Selection. Remembered profile paths remain inert host preferences;
selected intent remains process-local and provider activation remains behind
explicit Connect/reconnect.

Choose will statically validate current source bytes, durably remember the
validated path, then publish selected intent and increment profile generation
once. Save failure is fail-closed for the selection. Restore rereads and
validates the remembered current source without rewriting the preference or
spawning providers. Forget removes only the remembered path and has no runtime
effect, including while Connected. Clear Selection removes only process-local
selection and preserves the remembered preference.

The sanitized presentation will distinguish remembered-only from selected
intent without serializing any path or source-derived identity. New commands
will be registered only on the established Desktop Tauri capability surface.

## Implementation

- Choose statically validates current source bytes, validates the bounded
  remembered path, serializes the preference write with other desktop
  preference mutations, and publishes selected intent only after durable save
  and a final lifecycle check.
- Restore is an explicit host command. It rereads the remembered current
  source, applies the provider-only overlay validation, refreshes selected
  metadata, increments profile generation once, and never persists or starts
  providers.
- Forget is a separate preference-only host command. It is allowed while
  Connected when chat is idle and leaves selected intent, connection,
  provider activation, Effective Authority, and generation unchanged.
- Clear Selection remains disconnected-only and process-local; it preserves
  the remembered path and increments generation only when selection existed.
- Presentation adds `remembered` while retaining only sanitized configured
  metadata for selected intent. The frontend renders the three distinct
  inert states as `No profile remembered`, `Remembered — not restored`, and
  `Configured — providers inactive`; it never renders the path.
- `restore_trusted_profile` and `forget_trusted_profile` are registered in
  `generate_handler`, build-time command metadata, and the Desktop default
  capability. No generic filesystem, process, model bridge, dependency, or
  authority surface was added.

## Generation and authority review

Startup remembered-only state is generation 0. Choose and Restore each add one;
failed validation/save and Forget add none. Clear adds one only when it clears
an existing selection. Connect and Disconnect do not change profile
generation. Remembered state is not selected intent, Effective Authority,
advertised inventory, authorization, or model-visible state. Connect still
reads only selected process-local intent, and Refresh Authority does not
restore or validate the source.
