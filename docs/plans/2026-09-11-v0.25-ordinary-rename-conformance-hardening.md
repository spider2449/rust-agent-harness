# Task 292 — Ordinary `repo.rename-file` Conformance Hardening

Status: implementation and deterministic evidence for Task 292 only.

## Scope and verdict

This document records the deterministic hardening of the existing ordinary
`repo.rename-file` implementation against accepted ADR 0018. It does not add
authority, a reviewed HostExplicit route, an ADR, Desktop behavior, frontend
behavior, live certification, or release work.

The implementation keeps the existing one-at-most-one native effect boundary:

```text
capture -> revalidate -> one native no-replace rename -> independent proof
```

ADR 0018 does not acquire the future reviewed-route narrowing for ignored
paths.

## Focused deterministic test evidence

The rename module has 24 passing focused tests after hardening. They cover:

- clean same-directory success and same-volume cross-directory success;
- tracked destination absent from the worktree, staged destination, and
  intent-to-add destination;
- staged source content and mode divergence, conflict stages, and existing
  path/index collisions;
- merge, cherry-pick, revert, rebase, sequencer, and bisect marker refusal;
- source-parent and destination-parent replacement before and after the
  possible effect;
- forced same-volume refusal before the native boundary;
- exact-preimage native failure as `known_no_effect`;
- same-byte/new-identity source replacement as `uncertain`;
- generic absence observation failure as `uncertain`;
- destination identity mismatch, same-name source replacement, and Unix
  destination symlink substitution after a possible effect;
- the existing no-retry uncertain path and all existing path restrictions.

Every precondition test asserts zero counted rename attempts. Every successful
effect asserts one counted attempt. Fault paths assert one attempt and no
replay, rollback, cleanup, or compensation.

## Public and authority invariants

- Tool name remains `repo.rename-file`.
- Permission remains `PermissionLevel::Execute`.
- The four input fields, 1024-byte path bound, 1 MiB source bound, and
  `additionalProperties: false` remain unchanged.
- The five public statuses remain exactly `renamed_verified`,
  `known_no_effect`, `invalid_input`, `precondition_failed`, and `uncertain`.
- Public JSON result shapes remain unchanged.
- `RepositoryFileRenameAuthority`, `ToolRegistry`, and authorized dispatch
  semantics remain unchanged.
- No new mutation authority or broader target selection was created.
- No overwrite, copy-delete, `git mv`, shell/process move, temporary name,
  retry, replay, rollback, or automatic recovery was added.
- The per-repository mutation lease still covers capture, revalidation, the
  single native attempt, and proof. It is not claimed to defeat arbitrary
  external-process races.

frontend, provider behavior, Cargo files, dependencies, versions, tags,
releases, or live/destructive certification. ADR 0026 was not created and
