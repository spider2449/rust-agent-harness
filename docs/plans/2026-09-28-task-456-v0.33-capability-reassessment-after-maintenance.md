## Authority and decision

The product threshold requires a specific user problem, bounded contract,
authority-safe direction, certification plan, and meaningful gain over the
current route. No row has the first and last of these. Maintenance friction is
a real cost input, but it is not product demand. Task 427's closed recomposition
boundary, Task 428's directory decision, ADR 0027's single active repository,
and ADR 0030's exact runtime admission remain authoritative. Provider metadata
and model requests grant no authority. Tasks 430–432 corrected manifest
coverage, not WebView authority. There is no evidence to add HostExplicit #12,
union registries, model-selected repositories, automatic profile handoff, or
broader filesystem discovery.

**B — NO v0.33 PRODUCT CAPABILITY SELECTED.** Current evidence still does not
justify product expansion. The appropriate next lifecycle step is to **hold
v0.33 and continue evidence collection**. There is no evidenced release
blocker requiring a maintenance-only v0.33 release, and a version bump is not
needed to record completed maintenance on 0.32.0 source.

Recommended next task: a bounded normal-use evidence collection task only when
an interactive production Desktop session or concrete user report is available.
Record the exact prompt/workflow, expected and observed result, frequency or
severity, current workaround and its cost, and whether a product route is
actually missing. Reassess a single candidate only after that evidence exists.
This recommendation authorizes no production implementation, new authority,
release, or adjacent task here.
