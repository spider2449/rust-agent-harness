## Milestone summary

The release capability is **HostExplicit Reviewed Multi-File Edit Authoring**.
The connected-current Desktop route is:

```text
typed bounded multi-file request
 -> zero-effect Prepare
 -> complete backend-derived ordered review
 -> opaque ticket-only Confirm
 -> shared revalidation / D2
 -> HostExplicit Started
 -> authorized_tool_dispatch
 -> ToolRegistry
 -> existing repo.edit-files / ADR 0014
 -> strict result classification / descriptive repository refresh
```

The bounded contract is 1–4 existing clean HEAD-tracked regular strict-UTF-8
files, 1–16 exact literal replacements per target, and at most 64 replacements
total. The host derives exact original-snapshot matching, preimages,
postimages, hashes, lengths, and canonical path order. The operation is
explicitly non-atomic and preserves `ok`, `invalid_target`,
`precondition_failed`, `failed_known_no_effect`, `partial_effect`, and
`uncertain`. There is no retry, replay, prefix continuation, rollback,
restore-preimage, transaction, automatic Stage, or automatic Commit.

The exact eight eligible Tools are:

```text
fs.read
repo.file-info
repo.status
repo.diff
repo.diff-staged
repo.create-branch
repo.patch
repo.edit-files
```

`repo.create-file`, `repo.delete-file`, `repo.rename-file`,
`repo.create-directory`, `repo.commit`, MCP Tools, Process Plugin Tools, and
unknown Tools remain ineligible. There is no wildcard or category-based
eligibility. Model output is never authorization; frontend input/presentation,
permission classification, Trusted Profile, and provider metadata cannot create
or self-enable mutation authority.

## Ticket, activity, and refresh semantics

Prepare is zero-effect and returns a complete backend-derived review. The
opaque ticket is process-local, in-memory, single-use, exact-change/currentness-
bound, and valid for an inclusive five-minute TTL. Confirm and Cancel receive
only `{ ticketId }`. Generic HostExplicit activity has a separate RAH-generated
non-authority activity ID: it is not the ticket, is not derived from the
ticket, cannot Confirm, cannot Cancel, and the ticket/source-bearing review is
absent from generic activity.

Task 263 Attempt 1 discovered the ticket-under-`invocationId` leak before
Confirm with zero effect. Attempt 2 corrected the privacy defect and passed on
a fresh repository. The chronology is retained rather than erased or relabeled.

`repo.patch` and `repo.edit-files` invalidate stale reviewed Commit
authorization at the Started boundary. Refresh is descriptive only. The
narrow empty-index fallback retains descriptive status/diff refresh when
optional Commit preparation is unavailable, without fabricating or granting
Commit authority. Stage and reviewed Commit remain separate explicit actions.
