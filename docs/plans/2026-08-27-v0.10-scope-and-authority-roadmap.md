# Task 116 — RAH v0.10 scope and authority roadmap

## Audited starting state

Research began from clean `master` at
`0bcc985e8c275f4d26814913947f0bf49dc650c2`. RAH v0.9 repository authoring,
Task 115B cross-restart Resume, Actions Cleanup, and PowerShell 5.1 baseline
manager compatibility are complete. The certified Windows live baseline remains
exactly `codex-cli 0.149.0`; no v0.10 roadmap existed.

Desktop currently resolves `RAH_CODEX_EXECUTABLE` or falls back to `codex` on
PATH. Its llama.cpp selection is an already-running fixed endpoint preset,
`http://127.0.0.1:8080/v1`; it has no executable/model/process authority.

## Candidate matrix summary

| Candidate group | Result | Authority / ADR conclusion |
| --- | --- | --- |
| Certified Codex explicit selection and exact-store discovery | Adopt | No new model or host authority; no ADR when fresh verification uses existing explicit adapter seam |
| Local loopback llama.cpp endpoint configuration | Conditional follow-on | No model/process authority and no ADR only while closed, no-credential, no-launch, loopback-only |
| Persisted inactive preferences | Pair with adopted work when needed | Durable data is not active authority; no ADR if startup never activates it |
| llama.cpp executable/GGUF process launcher | Defer | New bounded provider lifecycle authority; new ADR required before implementation |
| Conversation export/import | Defer | Useful but lower value; data only and no authority restore |
| Model-selected staging; commit/history/ref; network MCP; PluginManager; profile reload; delete/rename/mkdir | Defer | Each expands a separate authority class and needs its own ADR research/design |

## Selected recommendation

v0.10 should center on **Desktop Certified Codex Baseline Discovery and
Selection**. Rust should resolve candidates in this order:

```text
explicit RAH_CODEX_EXECUTABLE override
  -> freshly verified exact codex-baselines 0.149.0 candidate
  -> existing PATH compatibility fallback
```

The verified baseline must win over PATH. Store layout alone is insufficient;
the existing manifest/native-form/platform/architecture/SHA-256/reported-version
checks must be applied. JavaScript receives only source/version/status, never
an absolute executable path. An explicitly selected baseline supplies an
absolute path to the existing adapter, so that connection does not consult
PATH.

The recommended first local-provider addition remains a separate endpoint-only
task: explicit normalized loopback `http://127.0.0.1:<port>/v1`, no credentials,
no arbitrary URLs, and no automatic connection. It must not be combined with
process launch.

## Rejected or deferred alternatives

RAH should not own `llama-server.exe` or GGUF locations in v0.10. Endpoint-only
configuration does not need either. A future launcher would not make RAH an
inference engine, but it would make RAH the owner of an external provider
process and therefore needs a distinct contract for executable/model identity,
closed argv, environment/cwd, GPU/context policy, bounded diagnostics,
readiness, shutdown, crash/restart, stale-resource replacement, persistence,
and Windows Job Object handling. Existing process adapters are useful evidence
but insufficient authority. Do not use `shell.exec`.

Persist only inactive, bounded desired state such as baseline source identity,
fixed supported version, provider/model selection, and a normalized loopback
endpoint. Do not persist raw executable/GGUF paths, credentials, arbitrary URLs,
argv/environment, server state, repository/tool/profile/permission authority,
or native provider state. On restart, the host is disconnected and must freshly
verify and explicitly activate any configuration.

## ADR conclusion

No ADR is needed for the selected A/B scope or for a strictly local endpoint
configuration because both are Desktop-private host configuration that uses an
existing adapter seam and grants no new authority. A new ADR is mandatory
before a RAH-owned llama.cpp launcher, network endpoint expansion, dynamic
profile reload, provider lifecycle management, or repository/index/history
authority expansion. ADR 0011 remains a static composition boundary and must
not be broadened.

## Expected next task

**Task 117 — Desktop Certified Codex Baseline Discovery and Selection**:
implement only a Rust-side exact-version resolver with strict baseline
verification, source/status presentation, override/store/PATH precedence tests,
and certified Windows live connection evidence. Do not add persistence, llama
process launch, new dependencies, or an ADR in that task.
