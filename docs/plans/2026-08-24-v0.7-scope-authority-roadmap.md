# Task 070 Plan — RAH v0.7 Scope and Authority Roadmap

## Scope

Research/design only, after released RAH v0.6.0. No Rust, Cargo, public API,
permission vocabulary, trusted-profile schema, Generic Tool Bridge, ADR, tag,
or release-preparation changes are authorized.

## Findings and decision

The primary v0.7 direction is **B: bounded multi-replacement in one existing
tracked file**, expressed as a strict extension of `repo.patch`. It provides a
meaningful coding-agent step while retaining the smallest authority increment:
one already-authorized target class and one final single-file replacement.

`repo.create`, multi-file transactions, unified patches, Git commit authority,
persistence, network MCP, PluginManager, dynamic profile reload, and a
hardening-only release are documented and deliberately deferred. The full
decision matrix and authority analysis are in
`docs/RAH_V0.7_SCOPE_AUTHORITY_ROADMAP.md`.

## Follow-up sequence

1. Task 071 (research/design only): determine exact `repo.patch` list schema,
   fixed bounds, snapshot/overlap semantics, outcome taxonomy, tests, live
   gate, and whether ADR 0012 needs an amendment or successor decision.

3. In a separately authorized implementation task, make the narrow tool and
   profile/bridge composition changes, then run deterministic and live gates.
4. Run the cross-platform/release review only after the capability is proven.
