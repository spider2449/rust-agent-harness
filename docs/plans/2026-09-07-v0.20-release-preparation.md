## Product claim

RAH v0.20 adds an explicit Desktop Host Tool invocation workflow for a closed
first-party Tool set. HostExplicit reuses connected-current Desktop composition
and the shared D2 current-definition/permission gate. It provides a human
Host action that does not depend on model Tool selection and creates no new
underlying capability authority.

## ADR 0021 / authority claim

Host explicit dispatch != runtime/model dynamic dispatch != capability
authorization. HostExplicit does not create repository, filesystem,
branch/ref, commit, provider, process, or network authority. Execute is not
generic repository authority; frontend, visibility, Effective Authority,
confirmation, model text, and provider metadata are not authority.

## D2 claim

D2 requires exact current Tool definition equality, including name,
description, input schema, and permission, current registry resolution, and
explicit current-permission membership in the host policy. It rejects before
execution, executes exactly once after admission, has no permission hierarchy,
and owns neither eligibility, provenance, outcome interpretation, replay, nor
rollback.

## Codex bridge claim

The Codex bridge retains thread/turn ownership, private alias, replay and
deduplication, cancellation, response translation, and AgentEvent lifecycle.
It authorizes before `ToolStarted` and revalidates at execution. A captured
permission change is stale even if the replacement would otherwise be allowed.
This is admission hardening, not a model Tool-selection guarantee.

## Desktop HostExplicit claim

HostExplicit is connected-current only. Current registry, definitions, allowed
policy, selected repository/context, and bound generations are retained;
stale/disconnected state fails closed. There is no silent reconnect, recompose,
provider activation, Trusted Profile restore, or disconnected execution.

## Typed inputs

`fs.read` and `repo.file-info` use `path`; `repo.status`, `repo.diff`, and
`repo.diff-staged` use `{}`; branch Prepare uses `name`; branch Confirm accepts
ticket ID only. No generic ToolName/arbitrary JSON route exists.

## Branch review/ticket

Prepare has zero Tool execution and zero Git effect. Sanitized review precedes
explicit Confirm. The opaque ticket is process-local, in-memory,
non-persistent, single-use, Tool/input/composition-bound, and expires after
five minutes. Confirm consumes and revalidates it, does not auto-reprepare or
retry, then enters D2 and ADR 0020 authority.

## Concurrency / provenance

One HostExplicit action maximum; no host action during ModelTurn and no model
turn during HostPrepared or HostRunning; read-only actions participate; no
queue or retry. States are Idle, ModelTurn, HostPrepared, HostRunning.
Desktop-private provenance is `host_explicit`, not model lifecycle, with no
AgentEvent schema change.
