## Accepted contracts and candidate shapes

ADR 0012 authorizes `repo.patch` only for one existing clean HEAD-tracked regular UTF-8 file with exact length/hash and literal replacements. It explicitly requires a later authority decision for untracked files. Its HEAD/index equality and Git-state revalidation are fundamental to the present tracked form. ADR 0014 separately authorizes `repo.edit-files` for one to four clean HEAD-tracked files, with ordered, non-atomic commits and `partial_effect` semantics. ADR 0013 authorizes `repo.create-file` only for a path absent from HEAD, all index stages, and worktree; exclusive no-clobber creation is its commit point. ADRs 0027 and 0029 preserve active-only repository composition and selected-worktree identity. Architecture and security docs place these behind private host policy, Execute, and ToolRegistry; an effective Tool inventory is not target authorization.

| Shape | Assessment |
| --- | --- |
| A. Extend `repo.edit-files` | Its name is plausible, but its accepted multi-file tracked-clean change set and non-atomic prefix outcomes would gain a second target class. Mixing tracked and untracked targets changes Git preconditions and authority under the same policy. Reject for the first correction capability. |
| B. Extend `repo.patch` | Literal replacement, complete-postimage preparation, and one-file outcome discipline are reusable. Its current HEAD/index baseline is intentionally tracked-only; treating an untracked file as a fake HEAD entry would obscure the contract. Reject semantic widening of the existing Tool. |
| C. Extend `repo.create-file` | Existing-target replacement contradicts exclusive creation, no-clobber, and its partial-create failure model. Reject. |

It can reuse validated path, Git-observation, lease, text transformation, temporary, and native replacement primitives where their invariants apply. Its schema and policy must state the new target class explicitly. |
| E. Other existing abstraction | No reviewed abstraction authorizes correction of an already-existing untracked target. Generic filesystem writing and staging first do not satisfy this workflow. |

## Selected boundary and Git state

**A — SELECT v0.33 CAPABILITY: BOUNDED UNTRACKED-FILE CORRECTION.** Select one ordinary Tool request to perform bounded exact literal replacement(s) in exactly one already-existing, regular, strict-UTF-8 text file beneath the currently active admitted repository. The file must remain untracked after success. Use an expected whole-file SHA-256 and byte length, unique exact literal match(es), bounded request and postimage sizes, and a no-op result when replacement text equals original text. A final Tool name and schema can be fixed in the implementation task; the authority class is fixed here. This is new worktree-content authority, separate from the accepted tracked-file and create-only policies. It adds no index, ref, history, process, shell, or general filesystem authority. `PermissionLevel::Execute` alone is insufficient; trusted host construction and ToolRegistry dispatch remain mandatory. A new ordinary Tool does not change HostExplicit eligibility: it remains exactly 11.

For this first version, **untracked** means: the path is absent from current HEAD and from every index stage (including intent-to-add), is not ignored under the selected repository's Git rules, and is present in the selected worktree as a regular file. Check the path literally, including Git's case behavior on Windows; reject ambiguous aliases or case collisions rather than guessing. A staged-added path and a path deleted from the index but still in HEAD are excluded. A path tracked on another branch is eligible only if absent from *current* HEAD and index and otherwise passes all checks; another branch does not grant authority. Ignored files are excluded, including generated and local configuration material. Reject submodules, gitlinks, nested repositories and any target whose ancestry crosses a nested `.git` boundary. For linked worktrees, use the admitted active worktree's own root, HEAD, index, and identity; reject unsupported or ambiguous identity rather than affecting a sibling worktree. Recheck Git state immediately before replacement and after observation.

The host must resolve a constrained repository-relative logical path inside the active root and reject traversal, absolute/native path forms, `.git`, alternate streams, symlinks, junctions, reparse points, special files, hard-link aliases where identity proof requires rejection, and parent/root changes. Existing repository boundary validation and shared mutation lease should be reused only after verifying they enforce this exact target class. Active selection is host-owned; no model-selected repository, inactive executable registry, union registry, or live switch is introduced. Restart restores zero executable repository authority.

## Mutation and outcome contract

Capture bounded raw preimage, length/hash, target and parent identities, worktree identity, and HEAD/index/ref observations under the repository lease. Prepare and flush the complete postimage in an exclusive host-named same-directory temporary file. Revalidate content, path, identity, Git state, and temporary immediately before one native replacement attempt. Do not write in place or retry. Preserve supported mode/attributes as the existing single-file patch contract requires. Verify exact postimage, target class, root/parent, and unchanged Git state after the attempt. A stale hash, length, missing match, changed tracking/ignore state, or changed identity must refuse with proven no target mutation before the commit point. If a post-commit observation, cleanup, cancellation, or OS outcome cannot prove the effect, report uncertainty; never infer rollback or automatically replay. Retain bounded host-private evidence and audit ambiguous temporary cleanup. A native replacement can race an external process, so the implementation must preserve ADR 0012's conservative TOCTOU boundary and must not claim cross-process exclusivity or crash durability.

## Implementation acceptance contract

Positive: create an untracked text file through supported authority, correct it while untracked, verify exact bytes, unchanged HEAD/index/refs, untracked status, and unrelated files unchanged. Include no-op and multiple bounded exact replacements if the schema offers them.

Negative: refuse tracked, staged-added, intent-to-add, index-deleted/HEAD-present, ignored, missing, directory, binary/invalid UTF-8, oversized, stale, ambiguous-match, alias/case-collision, outside-root, traversal, symlink/reparse/hard-link escape, nested repository, and unsupported worktree identities. Verify pre-commit failures have no target effect; exercise replacement failure, concurrent change, lost post-observation, and temporary cleanup uncertainty without retry or silent corruption. Prove linked-worktree confinement and active/inactive separation on supported platforms.

Regression: `repo.patch` and `repo.edit-files` retain tracked-only semantics; `repo.create-file` stays create-only; HostExplicit remains 11; no union ToolRegistry, model-selected repository, automatic stage/commit, or broadened Trusted Profile authority. Deterministic Windows and Unix tests should cover the selected native replacement behavior.

Non-goals: arbitrary paths or non-repository files, directories, ignored files, binary/invalid-text editing, recursive parent creation, tracked/staged editing through this Tool, generic full-file write/truncation, deletion, rename, automatic staging/commit, repository switching, HostExplicit enrollment, rollback, replay, and broad filesystem/process authority.
