## Product and lifecycle contract carried into release claims

Explicit Close preserves the active member in admitted membership as inactive,
leaves membership generation unchanged, removes active `DesktopRepository`
and active repository executable authority, and advances repository
generation exactly once with checked arithmetic. Rejected or repeated Close
does not churn generation. Later explicit activation builds fresh repository
currentness. The certified measured sequence `1 → 2 → 3 → 4 → 5` is evidence
from one run, not a global generation guarantee.

The confirmation captures expected `RepositoryMemberId` and repository
generation as equality/currentness guards, not authority. A stale A request
after B becomes active returns `active_changed`, preserves B, and cannot be
reinterpreted against B. Async repository observation may prepare outside
lifecycle coordination; final publication checks the captured repository,
member, and generation under lifecycle coordination, so stale A cannot publish
after Close or switch.

Close requires the existing runtime/provider lifecycle to be fully
disconnected. It does not implicitly Disconnect. Started or uncertain owners
remain owned and block Close. Close is not cancellation, rollback, replay, or
compensation. It performs no worktree or Git mutation, including Stage,
Unstage, Commit, branch/ref/history, `.git`, or network Git. It does not mutate
remembered catalog bytes, delete completed transcript persistence, or
automatically Resume it. Effective Authority after Close has no active
repository authority; admitted membership alone grants none.
