# Task 259 — RAH v0.22 Shared Non-Effectful Multi-File Preparation

## Status

Implementation complete. This task adds the shared `rah-tools` preparation and
revalidation foundation authorized by ADR 0023. It does not implement the
HostExplicit Desktop route or change HostExplicit eligibility.

## Implementation

`rah-tools` now exposes `RepositoryMultiFileEditPreparer` and the closed typed
request types `RepositoryMultiFileEditPreparationRequest`,
`RepositoryMultiFileEditPreparationTarget`, and
`RepositoryMultiFileEditTextReplacement`.

Successful preparation retains a capability-specific immutable plan containing
canonical host-sorted targets, target and parent identity observations, clean
tracked/index-consistent Git observations, strict UTF-8 original bytes,
literal match ranges, complete postimage bytes, hashes and lengths, and the
canonical existing `repo.edit-files` `ToolInput`. Its public review contains
all target paths, ordinals, replacement ranges, complete escaped changed text,
preimage/postimage hashes and lengths, matching semantics, protected
non-effects, and the non-atomic warning.

Preparation is read-only. It does not execute a `Tool`, invoke a native
replacement, create repository-adjacent temporary files, change target bytes,
change the index, stage or unstage, commit, change HEAD/refs/history, or invoke
a provider, model, or runtime.

`RepositoryMultiFileEditPreparer::revalidate` rebuilds the same read-only plan
from the retained canonical `repo.edit-files` input. It checks repository and
Git observations, target and parent identities, admission and mode, clean
tracked state, exact original bytes and hashes, replacement applicability,
postimages, canonical order, review identity, and the canonical ToolInput.
It has the same zero-effect guarantees as preparation.

Neutral failure classes are `InvalidInput`, `InvalidTarget`,
`PreconditionChanged`, `Stale`, and `ReviewTooLarge`. Complete changed
material, serialized review, and retained preparation material are rejected
without truncation when their bounds are exceeded. The existing effectful
`repo.edit-files` policy and its six result classes remain the mutation path.

## Deterministic coverage

Focused `rah-tools` unit tests cover:

- one through four targets, exact hashes/lengths/postimages, and host order;
- unchanged worktree/index/HEAD/ref state and no repository temporary files;
- same-original-snapshot literal matching, missing/multiple/duplicate/
  overlapping/no-op rejection, and empty removal text;
- target, replacement, request, file, aggregate, review, and retained-state
  bounds;
- untracked, dirty, staged/index-divergent, strict UTF-8, link, special-file,
  hard-link, path, and supported mode/attribute admission through the shared
  multi-file policy; and
- unchanged revalidation plus byte, target identity, and protected Git drift
  rejection without mutation.

Existing `repo.edit-files` preflight and Tool tests remain in the same policy
path; no Desktop, frontend, permission, Trusted Profile, ADR, dependency, or
package-version changes are part of this task.
