## Result

SELECT: A1 — host-bounded local branch creation at exact captured HEAD.

v0.19 should create exactly one absent ordinary local branch under refs/heads/name

HEAD, index, or worktree state; it has no tracking, arbitrary start point,

RepositoryBranchCreationPolicy. Existing commit, index, file/directory,
Execute, and repository-selection authority do not imply it. A new ADR is
required after Task 223 research confirms the contract.

research-only and is not started here.

## Current product capabilities

RAH supplies repository observation (repo.file-info, repo.status, repo.diff,
repo.diff-staged); bounded worktree edits (repo.patch, repo.edit-files);
one-file creation/deletion/rename and directory-leaf creation; human-owned
Stage/Unstage; reviewed staged snapshot and host-authorized message-only
commit; repository-scoped SQLite persistence with explicit Resume; and
repository/model/profile/connection currentness.

Trusted Profiles are host-composed and support inert source-path persistence,

## Current authority planes

Observation is distinct from bounded existing-file mutation, file creation,
file deletion, file rename, directory creation, directory-tree mutation, index
mutation, reviewed commit/history mutation, local branch/ref mutation,
HEAD/worktree checkout transition, remote/network Git, and provider/network
authority.

ADR 0016 permits one reviewed normal commit advancing only the already-attached
branch and expressly excludes branch creation, switching, arbitrary ref update,
and remote Git. ADRs 0017–0019 keep delete, rename, and leaf-directory
creation as separate host-owned policies. ADR 0011 keeps effective profile
composition immutable and defers hot reload. Execute, Tool registration, model
output, provider metadata, and UI state never grant authority.

## A1 — local branch creation analysis

### Contract and authority

The future request contains one logical branch name. The host binds selected
canonical repository/identity, repository generation, host-approved Git
executable, symbolic HEAD target, attached branch, exact HEAD commit, and
target absence. The only effect is creating absent refs/heads/name at captured
OID. Normal target reflog creation is permitted only when Git creates it;
manual reflog mutation is not.

No input may select root, cwd, executable, argv, environment, ref namespace,
SHA/start point, remote, force, overwrite, delete, rename, tracking,
checkout/switch/detach, tags, fetch/pull/push. Initially reject detached or
unborn HEAD, bare repositories, linked worktrees, malformed metadata, and
special merge/rebase/cherry-pick/revert/bisect/sequencer state. Task 223 can
re-evaluate only with evidence.

RepositoryBranchCreationPolicy is necessary. Ref creation is a persistent
repository namespace effect. Commit authority binds a reviewed index and moves
only existing attached HEAD; it expressly does not authorize branch creation.
Index, file/directory, profile, Execute, ToolRegistry, model, and frontend
state cannot imply it.

### Name validation

Use a closed host validator; shell quoting is never a boundary. Git
check-ref-format rules prohibit components beginning with dot or ending lock
suffix; double dots; controls/DEL, spaces, tilde, caret, colon, question mark,
asterisk, opening bracket; leading/trailing or repeated slash; trailing dot;
at-open-brace; single at; and backslash. Branch mode also rejects leading dash.

v1 should be stricter: nonempty logical name only; reject dot/dotdot
components, leading dash, trailing dot or space, backslashes, dot-git-like
components, previous-checkout syntax, Unicode/platform aliases until
deterministic behavior is proved, and every namespace except host-built
refs/heads. Do not normalize model input into a different accepted name.
Fresh admission rejects exact target and both prefix collisions (foo and
foo/bar), including packed refs. Windows case, trailing-dot/space, and
filesystem-ref aliases fail closed if identity is unclear. Git validation is
a compatibility check, not authority.

### Git execution and verification

Task 223 must compare fixed native git branch with host-derived name and OID
against a private tightly constrained compare-and-create git update-ref. Both
require canonical executable/cwd, no PATH lookup, shell, arbitrary argv/config/
environment, bounded output/deadline, and hardened Git environment. Branch
porcelain may consult tracking/config/reflog behavior; generic update-ref is
excluded by ADR 0016. The current hypothesis is a fixed update-ref transaction
only if research proves expected-absence, reflog, Git-version, and failure
semantics narrower. Do not choose for convenience.

Before attempt, capture repository identity, generation, symbolic HEAD/current
branch/OID equivalence, target absence, bounded loose-and-packed ref manifest,
and index/worktree fingerprints needed to prove non-effect. Hold the established
per-canonical repository mutation lease and immediately revalidate.

Verified success proves target equals captured OID; HEAD and attached branch/OID
are unchanged; index and worktree sentinels are unchanged; all pre-existing refs
are unchanged except target and permitted reflog. Results are invalid_input,
precondition_failed, branch_created_verified, known_no_effect, or uncertain;
exit status alone is insufficient. Timeout, cancellation, disconnect, crash,
lost response, or observer failure requires observation and no retry, replay,
delete, rollback, or switch-back.

### Dirty state, review, generations, conversations

A1 should allow dirty/staged state when attached HEAD and target-absence
preconditions hold: it neither materializes nor stages files. UI wording:
Create a new local branch at committed HEAD OID; uncommitted and staged changes
remain in this worktree and are not put on the new branch.

Reviewed commit authorization binds branch, old HEAD, raw/semantic index, and
tree. A1 changes none. Do not automatically revoke a valid review; final commit
revalidation remains authoritative. Refresh presentation if needed, but do not
add a repository/ref generation merely for A1: repository generation means
selected identity/context while A1 binds fresh ref observations. Any later
review threat model asserting unchanged refs must say so explicitly.

Conversation identity stays correct because checked-out branch and selected
repository namespace do not change. No provider or connection replacement is
needed. This is exactly unlike A2.

## A2 — branch switch analysis

A2 is RepositoryCheckoutOrBranchSwitchPolicy, not A1 plus one command. It
changes HEAD, worktree materialization, and possibly index. It must define
host-selected existing local target only; no detached/unborn state, linked
worktree, sparse checkout, submodule/gitlink, nested repository, sequencer
state, unsafe case/reparse paths, dirty/staged changes, untracked or ignored
collisions, locked Windows files, or a target checked out elsewhere.

A successful switch revokes review, refreshes repository presentation, makes
runtime stale/reconnect-required, and needs branch-aware Resume or explicit
no-Resume-across-switch semantics. Timeout can leave HEAD/index/worktree/locks
changed. No switch-back is safe. Research and ADR separately; defer.

## A3 — create-and-switch analysis

A3 combines A1 ref creation and A2 checkout. The branch can exist while checkout
fails or is uncertain; do not delete it or switch back automatically. It needs
two authorities and two effect manifests, including A2 full preconditions.
Convenience cannot combine these planes, so it is not v0.19 scope.

## Directory mutation candidates

repo.rename-file cannot imply directory/tree rename. A safe subtree move needs
one source, absent destination under existing validated parent, same-volume/no
fallback, full entry/type/identity/Git manifest, maximum file/byte limits, and
tracked/untracked/ignored policy. Reject symlink/junction/reparse, submodule,
nested repo, special nodes, collisions, and untracked/ignored children until
proved. Native rename does not eliminate TOCTOU or uncertainty. New policy/ADR;
defer.

C1 empty leaf deletion has limited value because Git does not track empty
directories. It still needs an explicit host/repository-bounded ordinary empty
leaf, no reparse traversal, one attempt, and no compensation; defer. C2
recursive tracked-tree deletion is materially destructive: full preimage/index
manifest, max files/bytes, untracked/ignored/submodule rules, and no rollback
after partial effect. repo.delete-file does not imply it; reject for now.

## Human Stage/Unstage boundary

Keep Stage/Unstage human-owned. They are the checkpoint between model-produced
worktree changes and the index a human reviews and authorizes for commit.
Model-visible operations let an untrusted model choose the reviewed set
iteratively after human attention moved, weakening ADR 0016 semantics. A model
request cannot transform existing index authority into that trust decision.

## Trusted Profile hot reload

v0.18 inert persistence proves only inactive desired-state restoration and
fresh explicit Restore/Connect load; it is not dynamic source observation.
Hot reload needs revocation, atomic provider replacement, currentness transition,
in-flight Tool ownership, timeout/disconnect uncertainty, credentials, watcher
identity/reparse handling, and no stale proxy Tool. It must never silently
expand active authority. New lifecycle/authority ADR work; defer.

## Network/provider candidates

Network MCP/Streamable HTTP is distinct from ADR 0015 bounded initial llama.cpp
endpoint. It needs host-owned NetworkEndpointPolicy, DNS/address identity
policy, TLS/peer identity policy, CredentialSource/OAuth lifecycle,
RedirectPolicy/proxy policy, ProviderNetworkAdmission/effective destination
disclosure, method/path/schema bounds, timeouts/retries, and external-effect
result semantics. DNS is not identity; no network isolation follows. Defer.

Plugin installation/update additionally needs download/provenance,
artifact/executable identity, placement, update admission, rollback/recovery,
lifecycle, and supply-chain policy. Reject for now.

## Recommended v0.19 milestone

Name: Bounded local branch creation at exact captured HEAD.

Product gap: RAH lacks a safe way to prepare a named local line of work without
changing active files.

Why selected: highest user value among remaining gaps with one narrow
host-bounded effect, no checkout plane, no network/supply-chain dependency,
deterministic Windows/Linux fixture proof, and no weakening of human review.
v0.18 currentness/persistence helps because A1 needs no conversation namespace
or provider lifecycle change; it does not make it existing authority.

One-release boundary: exactly one absent ordinary local branch at attached
captured HEAD, with hardening and later approved Desktop/Effective Authority
presentation. Exclude switch, checkout, arbitrary refs/start points, tracking,
remote Git, directory tree work, and model-facing baseline management.

## Authority decision

New authority class: YES. RepositoryBranchCreationPolicy is private, opaque,
host-owned, repository/generation-bound, short-lived, and composed only after
host construction.

Existing authority does not imply: ADR 0016 RepositoryCommitPolicy is reviewed
commit authority for existing attached branch and expressly excludes
branch/ref creation; index/worktree/file/directory policies, selection,
profiles, Execute, ToolRegistry, model, and UI do not imply it.

ADR required: yes, but only after Task 223 settles primitive, validator,
ref/reflog manifest, layouts/states, review interaction, and result taxonomy.
This task does not write it.

Model authority: at most a closed name request through a later Tool. Host binds
every security-relevant value and decides composition.

Frontend authority: presentation/review cannot create or restore authority.

## Security/fail-closed contract

Persistent effect: one local ref and permitted normal reflog metadata; no
intentional HEAD/index/worktree/network effect. Invalid input, ambiguous
repository/ref state, existence/collision, stale identity/generation,
unsupported state/layout, executable failure, or failed final revalidation
fails closed before mutation.

After a possible effect, timeout/cancel/disconnect/crash/lost response is
observed and classified; never replayed, retried, deleted, restored, checked
out, or compensated. No generic Git, shell, process, filesystem write, or
network authority is introduced.

## Deterministic validation strategy

Use ordinary fixture main at A, captured index/worktree sentinels, and clean,
dirty-unstaged, and staged variants. For permitted dirty variants verify one
target ref equals A; symbolic HEAD remains main; HEAD/index/worktree and every
pre-existing ref remain unchanged; reflog is bounded; child handles end.

Test invalid names (empty, dash, dot, traversal, double dots, at-open-brace,
controls, space, trailing dot/slash, repeated slash, backslash, colon,
question mark, asterisk, opening bracket, lock suffix, case aliases), existing
refs/prefix collisions, detached/unborn/bare/linked/special states, stale
bindings, lease serialization, one attempt, known-no-effect, and uncertain
post-observation. Core proof needs no model behavior.

## Windows live validation strategy

Use isolated ordinary Windows Git fixture through actual host-selected Git and
the permitted dirty/staged matrix. Prove target ref and unchanged
HEAD/index/worktree/ref manifest with process cleanup, recording sanitized
facts only. It is repository-authority live validation, not a model-selected
external Tool or Linux-support claim.

## Linux/cross-platform status

live-certified platform. Linux CI does not establish Linux Desktop live
certification; macOS stays conservative pending evidence.
