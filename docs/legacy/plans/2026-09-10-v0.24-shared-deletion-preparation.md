## Accepted boundary

ADR 0025 accepts a future human HostExplicit reviewed deletion route around
the existing ADR 0017 deletion authority. This task implements only the
shared zero-effect `rah-tools` preparation and revalidation foundation. ADR
0017 remains the sole underlying deletion mutation authority. No accepted ADR
is modified or broadened.

## Implementation boundary

`RepositoryDeleteFilePreparer` accepts the typed `{path}` request, captures a
clean HEAD-tracked regular-file preimage, derives the unchanged ordinary
`repo.delete-file` Tool input, builds a complete bounded review, retains an
opaque process-local preparation, and revalidates it without Tool execution
or deletion. Native paths, identities, raw index data, and mutation
primitives remain private.

## Ordinary Tool compatibility

The ordinary `repo.delete-file` Tool keeps its existing three-field closed
schema, 1 MiB source bound, binary behavior, five statuses, one-native-attempt
rule, and result semantics. Any shared capture refactoring preserves those
semantics. The reviewed route is deliberately narrower: strict UTF-8,
NUL-free, and at most 65536 raw bytes.

## Reviewed-route bounds and review rules

The canonical serialized `{path}` request is at most 8192 bytes and the
logical path is 1 through 1024 UTF-8 bytes under the existing safe logical
path grammar. The complete serialized review is at most 262144 bytes and the
retained preparation representation is accounted and bounded at 524288
bytes. Review content is complete and deterministic, ASCII-safe, and uses
fixed escapes for line endings, tabs, spaces, quotes, backslashes, controls,
format characters, and every non-ASCII scalar. The review includes the exact
preimage, derived hash and length, BOM/newline/content facts, 100644/100755
mode, HEAD/index relationships, expected unstaged-deletion effect,
non-effects, and permanent-effect warnings.

## Preparation and revalidation design

Preparation binds a process-local preparer identity, exact source bytes and
derived Tool preconditions, target identity/link count, repository/Git/.git
identities, HEAD/branch/tree/index/ref state, raw index bytes, complete review,
and a private preparation identity. Revalidation immediately re-observes the
same state and fails stale on any identity, source, Git, canonical-input,
review, or retained-state drift. Same-byte path replacement is stale because
target identity is protected.

## Deterministic evidence

prepared-state bounds, both supported modes where the platform permits,
