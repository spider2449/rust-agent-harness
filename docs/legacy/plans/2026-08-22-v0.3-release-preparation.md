# v0.3.0 release preparation plan

Date: 2026-08-22
Status: Complete

## Scope

Prepare the existing, verified v0.3 implementation for a release commit without
adding capabilities, committing, tagging, or pushing.

## Steps

1. Correct the Execute validation fixture naming so `process.test.echo` remains
   clearly test/live-validation infrastructure rather than a host capability.
2. Bump the workspace package version to `0.3.0` and refresh `Cargo.lock` with
   Cargo.
3. Update the release-facing documentation and add v0.3 release notes. Clearly
   separate public host capabilities from validation fixtures and retain the
   accepted security non-guarantees and post-v0.3 deferrals.
4. Run the deterministic workspace gate, validate Cargo metadata versions, and
   update the release-gate classification to `READY FOR RELEASE COMMIT` only if
   no blockers remain.

## Acceptance criteria

- All workspace packages using the workspace version resolve to `0.3.0`.
- No release document presents validation fixtures as public capabilities.
- The required v0.3 verified claims and explicit deferrals are documented.
- The specified formatting, check, test, lint, diff, and metadata validations
  pass.
