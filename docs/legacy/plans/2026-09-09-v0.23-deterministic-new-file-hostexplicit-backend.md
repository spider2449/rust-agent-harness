# Task 272 — Deterministic New-File HostExplicit Backend

## Scope and baseline

Task 272 implements the backend-only deterministic Desktop HostExplicit route
for the accepted ADR 0024 capability, `repo.create-file`, from baseline
`d718d28ed240b14d934c80bfc70c8ed420142597`. Frontend work, Windows live
certification, model prompts, provider HostExplicit routes, generic Tool JSON,
filesystem authority, automatic recovery, Stage, Commit, and Task 273 remain
out of scope.

ADR 0013 remains the sole underlying `RepositoryFileCreationPolicy` authority
and its six public result statuses. ADR 0021 remains authoritative for
connected-current HostExplicit dispatch, the coordinator, D2, ticket lifecycle,
and provenance. ADR 0024 owns the capability-specific reviewed human workflow;
the accepted ADRs were not modified.

## Reused foundation and composition

The Desktop route reuses Task 271's `RepositoryCreateFilePreparer` for all
non-effectful preparation and currentness revalidation. A retained
`Arc<RepositoryCreateFilePreparer>` is composed only when a repository is
selected, the current registry contains `repo.create-file`, and construction
from the host-selected Git executable and repository root succeeds. The
preparer is carried through `CurrentHostComposition` and must be the exact
same Arc instance at Confirm.

The exact nine-name HostExplicit allowlist is:

```text
fs.read
repo.file-info
repo.status
repo.diff
repo.diff-staged
repo.create-branch
repo.patch
repo.edit-files
repo.create-file
```

`repo.create-file` retains `RepositoryMutation`, `RepositoryFileCreation`,
and `repositoryBound = true` metadata. Provider-origin tools, directory,
delete, rename, commit, echo, MCP, Process Plugin, fixture, and unknown tools
remain ineligible.

## Typed reviewed workflow

The Desktop-private Prepare DTO is closed and accepts only `{path, content}`;
unknown fields are rejected. The response is the camelCase
`{ticketId, review}` `PreparedCreateFileResponse`. The complete ADR 0024
review is returned only through this bounded direct response and is not placed
in generic HostActivity or conversation history.

Prepare reserves the coordinator slot with `begin_prepare`, captures the
current connected composition, checks the exact current definition and
permission through non-effectful D2 preflight, and calls the shared preparer.
It reconstructs the exact ToolCall from `preparation.tool_input()`, stores the
opaque `PreparedHostPayload::CreateFile`, allocates ticket and activity IDs
independently, and finalizes once. Failed or oversized preparation aborts the
reservation and issues no ticket. Prepare performs zero Tool executions and
zero native creation attempts.

Confirm remains exactly ticket-only. It consumes the process-local, in-memory,
single-use, capability-specific five-minute ticket, checks generations,
composition, repository, definition, permission, and retained preparer Arc
identity, then calls shared `revalidate`. Only after those checks does it run
`authorize_tool_dispatch`, invalidate repository-bound reviewed Commit
authorization, emit HostExplicit Started, and spawn exactly one
`authorized_tool_dispatch` through the current ToolRegistry. There is no
replacement ticket, replay, cleanup, rollback, Stage, or Commit.

## Result and privacy boundaries

The backend has a create-file-specific strict classifier. `ok` requires one
JSON object with exactly `status`, `path`, `length`, and `sha256`, with all
three reviewed values matching the preparation. Each of
`invalid_target`, `precondition_failed`, `create_failed_known`,
`write_failed_known`, and `uncertain` requires one error JSON object with only
the exact `status` field. Contradictory or malformed output is
`Malformed`.

Terminal mapping is `ok -> ToolCompleted`, invalid target/precondition/create
failure -> `ToolError`, `write_failed_known -> PartialEffect`, and uncertain
or malformed -> `PossibleEffectUnknown`. Generic activity receives only a
status-only sanitized result for valid classifications; malformed output has
no result. Activity carries `source = host_explicit` and the independently
generated activity ID, never the ticket, content, hash, raw ToolInput, raw
ToolOutput, native path, or parent identity.

Every Started create-file outcome, including dispatch rejection and Tool
execution error, conservatively invalidates reviewed Commit authorization and
refreshes descriptively when the captured repository context remains current.
Possible partial or uncertain files are not removed or retried.

## Deterministic tests
