## Workflow implemented

- The `repo_create_file` form accepts only one repository-relative `path` and
  complete UTF-8 `content`. The path is required with a 1024-character UX
  bound; content may be empty and has a 262144-character UX bound.
- Prepare sends exactly `{ path, content }` to
  `host_prepare_repo_create_file`. No local filesystem write or local
  preflight is performed.
- The direct `{ ticketId, review }` response is shown only in the in-memory
  active review dialog. The review is rendered as complete backend-derived
  presentation, including target and parent state, expected effect, byte
  length, SHA-256, BOM, file intent, and all creation semantics.
- Complete escaped content is placed in a dedicated `<pre>` through
  `textContent`. CR/LF/CRLF, final EOF, control-character, and
  format/bidi/zero-width facts are shown from backend-provided fields.
- Backend-provided creation semantics, explicit non-effects, and warnings are
  rendered as safe text. The UI communicates no parent creation, Stage,
  Commit, index/HEAD/ref/history mutation, non-crash-atomic creation,
  possible empty/partial files, no cleanup, and no retry/replay.
- Confirm and Cancel remain ticket-only and send exactly
  `{ request: { ticketId: active.ticketId } }`. The existing single-active,
  disabled-after-first-action, close-to-Cancel, and in-memory ticket cleanup
  behavior is preserved.
- Create-file result presentation distinguishes `ok`, `invalid_target`,
  `precondition_failed`, `create_failed_known`, `write_failed_known`, and
  `uncertain`. `write_failed_known` is explicitly presented as a possible
  empty/partial-file effect requiring manual repository inspection;
  `uncertain` does not infer unchanged state and offers no retry or recovery
  action.
- Generic HostActivity remains source/ticket-free and retains
  `Host action — not Model` provenance. The complete review is not copied into
  activity, transcript, persistence, storage, URLs, or generic result data.
