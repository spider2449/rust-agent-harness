## 3. Task 207 / 207A / 207B chronology

### Task 207 - Windows Desktop External Provider Live Certification

Task 207 exercised the intended Windows Desktop path from Trusted Profile
selection and Connect through external-provider composition, Effective
Authority, Codex advertisement, external Tool execution, conservative
repository/review invalidation, Disconnect, and provider cleanup.

Provider selection, admission, composition, advertisement, and lifecycle
ownership were demonstrated. The model-selected external Tool execution
portion was not established, so Task 207 did not meet its complete live gate.

### Task 207A - Codex live Tool-dispatch certification hardening

Task 207A removed the possibility that a model-predicted public marker could be
mistaken for provider execution. The standalone MCP and Process Plugin gates
require all of the following: `ToolRequested=1`, `ToolStarted=1`,
`ToolFinished=1`, the exact public Tool identity, exact arguments, a fresh
hidden per-run provider nonce, provider execution count one, continuation after
`ToolFinished`, terminal `Completed`, and provider reaping/unlock.

The tested current ChatGPT-auth runs completed with `requested=0`,
`started=0`, `finished=0`, provider execution zero, and terminal `Completed`.
The hardened gates correctly failed closed. The hidden nonce was not exposed
to the model and could not be supplied by final assistant text.

### Task 207B - Codex live Tool-selection compatibility research

Task 207B compared the certified `codex-cli 0.149.0` with `gpt-5.6-terra` and
`gpt-5.6-sol` against newer `codex-cli 0.153.4` with `gpt-5.6-terra`. Both MCP
and Process Plugin runs remained `0/0/0` with provider execution zero.

The comparison found that `dynamicTools`, `DynamicToolCallParams`,
`DynamicToolCallResponse`, the dynamic function schema, and `deferLoading`
remain compatible. Neither tested Codex path provides host-side exact-tool or
generic required-tool forcing. No reproducible RAH defect was found, and the
negative newer comparison does not justify baseline migration.

## 11. Security implications

This task creates no new authority class and changes no production Rust,
permission, Trusted Profile, ToolRegistry, provider, repository, or Codex
authority behavior. No ADR is required.

The selected disposition is security-preserving because it retains the
hardened acceptance gate and treats the missing Tool request as missing
evidence, not as an implicit success. A final assistant message, provider
metadata, advertised schema, or frontend presentation cannot manufacture
authorization or provider execution.

The hidden nonce is useful as a positive-proof condition only: if it is
returned with the exact lifecycle and provider count, it corroborates actual
fixture execution. Its absence in these runs does not prove that all external
providers are harmless, that no ambient effects are possible, or that a
rollback exists. The existing distinctions among observation, bounded
worktree mutation, index mutation, and reviewed commit/history mutation remain
separate.

## 14. Preconditions for future re-certification

External execution may be revisited only if new evidence provides a supported
production path, such as:

- a currently supported ChatGPT-auth model begins producing actual dynamic Tool
  calls;
- Codex adds host-controlled required/exact Tool selection usable without
  changing production authority semantics;
- a future Codex version repeatedly restores real `ToolRequested` with the same
  hardened fixture; or
- another supported production model/runtime path produces the full
  hidden-nonce-backed lifecycle.

The future gate must continue to use production semantics and must not bypass
the Generic Tool Bridge, directly invoke a provider `ToolRegistry` as a
substitute, inject a fake `ToolRequested` event, weaken permissions/security,
or turn a test seam into production authority.

A positive certification must still require all of the following:

- `requested=1`;
- `started=1`;
- `finished=1`;
- provider execution count `=1`;
- the correct hidden nonce;
- continuation after `ToolFinished`;
- terminal `Completed`; and
- cleanup proof, including provider reaping/unlock.

This gate must not be loosened.
