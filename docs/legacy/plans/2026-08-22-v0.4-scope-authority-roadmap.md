# v0.4 scope and authority roadmap plan

## Scope

Research the next RAH release without changing production code, protocol types,
dependencies, or accepted ADRs.

## Method

1. Treat the v0.3 release gate, security model, accepted ADRs through ADR 0010,
   and the v0.3 worktree-mutation research as the evidence baseline.
2. Compare destructive worktree authority, history/ref authority, hardening, and
   higher-level runtime/product capability against authority, testability, and
   cross-platform cost.
3. Recommend one bounded v0.4 theme and an ordered follow-up sequence without
   beginning implementation or drafting ADR 0011.

## Deliverable

- Add `docs/RAH_V0.4_SCOPE_AUTHORITY_ROADMAP.md`.
- Clearly distinguish VERIFIED, IMPLEMENTED, PLANNED, and DEFERRED claims.
- Keep the proposed release within the existing index-only repository-mutation
  boundary unless new evidence justifies an ADR-led expansion.
