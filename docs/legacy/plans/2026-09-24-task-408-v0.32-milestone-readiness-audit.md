## 4. Current `repo.list` contract

Current implementation: `crates/rah-tools/src/repository_list.rs`, with shared
inventory/current-worktree handling in `repository_observer.rs` and boundary
checks in `repository_boundary.rs`.

| Contract field | Current behavior |
| --- | --- |
| Tool name / permission | `repo.list`; `PermissionLevel::Execute`. |
| Request | Closed JSON object with optional string `path`; `{}` means selected repository root. Unknown fields and non-object input fail. Request is at most 4 KiB. |
| Path | 1–1024 UTF-8 bytes, slash-separated, repository-relative. Empty, absolute, trailing/empty components, `.`, `..`, `.git`/`.GIT`, backslash, colon, and NUL are rejected. No depth, recursion, repository, worktree, member, root, Git args, cwd, environment, timeout, or cap fields. |
| Repository scoping | Host constructs the observer for the host-selected active repository. No repository selector exists in Tool input. Only the selected active worktree is observed. |
| Inventory | Fixed `git --no-pager ls-files --cached --deduplicate -z --full-name --`. Git supplies tracked inventory only; the host performs validation, current-worktree classification, and projection. |
| Listing | Direct children only. Direct files have kind `file`; directory entries are synthesized from eligible tracked descendants and have kind `directory`. Physical empty/untracked-only directories are not enumerated. The requested directory itself is not returned. |
| Ordering/bounds | Deduplicated lexical repository-relative UTF-8 byte order; first 128 results; deterministic `complete=false` and `truncation_reason="result_limit"` on saturation. Request 4 KiB, logical paths 1 KiB, inventory stdout 4 MiB, 100,000 records, normalized output 128 KiB, and total time 15 seconds. These are fixed, not model-adjustable. |
| Response | One JSON content item: `status`, `consistency="best_effort"`, `path` (root is `null`), `complete`, `truncation_reason`, `entries[{path,kind}]`, and omission counters `non_addressable_path`, `non_regular`, `changed_or_missing`. No file content is returned. |
| Errors | Invalid schema/path/target, file-as-directory, not-found directory, unsafe boundary, malformed/overflow/failed inventory, timeout, identity/Git replacement, or oversized serialization return sanitized ToolError and no partial list. Unknown/untracked-only/ignored-only prefixes are errors, not ambiguous empty success. |
| Visibility | Clean, modified, staged-new, and tracked paths matching ignore rules can be listed. Deleted, sparse-omitted, untracked, ignored-untracked, and non-regular candidates are omitted and accounted for by the frozen categories. Invalid UTF-8 paths are not lossy-converted; they are non-addressable omissions. |
| Boundaries | No-follow current-candidate inspection; nested `.git`/`.GIT`, unsafe directory symlink/junction/reparse ancestry, and nested repository boundaries reject the whole observation. Symlink files are not followed. Gitlinks/submodules are not traversed; contents are not disclosed. |
| Currentness | Existing repository lease and identity/Git revalidation bracket bounded observation. Best-effort only: no transaction/snapshot, race-free TOCTOU, global Git lock, automatic retry, rollback, or replay claim. |
| Privacy | Only safe repository-relative names, kinds, bounded completion state, and omission counts. No absolute roots, filesystem IDs, private/common Git paths, worktree registration, executable/profile path, cwd/environment, stderr, handles, IDs, generations, or persisted browse history. |

`repo.list` is separate from `repo.search` (which requires non-empty `mode` and
`query` and supports only its released `path|text` matching contract),
`fs.read` (reads one supplied file), `repo.file-info` (file metadata), and
`repo.status` (working-tree change state). It is not a directory mode on any
of those Tools and it does not read contents.

## 8. Corrected behavior history

The first Windows live run (Task 379) failed on ordinary nested navigation:
`{"path":"crates/alpha/src"}` returned a sanitized boundary-observation
failure after `{}`, `crates`, and `crates/alpha` had succeeded. The failure was
kept as a blocker.

Task 380 traced the rejection to missing tracked ancestors under sparse
checkout and made a narrow `nearest_existing_ancestor()` correction. Task 381
independently found that this correction could continue upward past an
existing symlink ancestor, weakening the boundary. Task 381-A changed the
invariant to **missing → ascend exactly one lexical parent; existing → classify
and terminate**. Only ordinary directories are accepted; symlink/junction/
reparse points, files, nested Git boundaries, and non-NotFound errors fail
closed. Task 381-B independently reviewed and passed that correction.

The production correction is in commit
`9e2e4c2f05ae877ba5739f364fdd3db3824b4736` (`fix: harden repository listing
boundary validation`). Regression tests in `repository_boundary.rs` prevent
the existing-object skip from returning. The Task 380/381/381-A/B and Task 382
records document the history; it was not erased by the final PASS.
