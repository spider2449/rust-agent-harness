# Task 229B — v0.19 Live Certification Disposition Decision

## Status

COMPLETE — disposition recorded; v0.19 is not declared release-ready.

## Decision

Select **Option B — Host-driven Windows live effect certification** before the
v0.19 milestone audit.

The next task is **Task 229C — Host-Driven Windows Desktop repo.create-branch
Live Effect Certification**. It will invoke the same production path on a
disposable real Windows Git repository:

```text
DesktopRepository
 -> RepositoryBranchCreationAuthority
 -> RepositoryBranchCreationTool
 -> Desktop ToolRegistry
 -> ToolRegistry dispatch
```

The live certification target is the bounded authority/effect plane, not model
selection. It must prove creation of one branch at the exact committed `HEAD`,
without switching, while preserving staged and unstaged state, the fixed
reflog contract, reviewed-commit authorization, repository/model/profile/
connection generations, `Current` connection state, Effective Authority, and
the absence of provider/profile side effects.

The result must not be relabeled as model-driven. In particular, this task and
Task 229C do not claim model-selected `ToolRequested` / `ToolStarted` /
`ToolFinished` dispatch.

## Evidence disposition

The authoritative checkpoint is:

- commit: `f12871a8a5e1b048e147df9c9b2e3d65a0e3bd43`
- exact-head CI: `34034804437` — PASS

Two bounded attempts through the same certified Codex gate (`0.149.0`, the
recorded binary SHA, `gpt-5.6-terra`) produced `ToolRequested=0`,
`ToolStarted=0`, and `ToolFinished=0` on each attempt. Attempt 1 had no target

effectful `ToolStarted`, and no retry followed. Therefore model-selected
Windows live branch execution is not established. The zero-dispatch evidence
does not infer an RAH branch-mutation failure.

Tool selection by the model is not authorization. Model failure to request a
Tool is not evidence that host authority is broken. The host owns and
explicitly composes authority; the registry and connected/current advertisement
are independently established facts.

Two bounded attempts are sufficient to establish that model-selected dispatch
is currently unproven. Further prompt or model sampling has diminishing
certification value and would risk turning certification into retry-until-pass
evidence or conflating model/Codex migration with the v0.19 branch-authority
scope.

## Security and release boundary

Option B is an independent live check of the host-owned effect plane. It does
not weaken the accepted authority separation in ADR 0020: the model supplies
only the bounded logical name, while the host binds the repository, `HEAD`,
Git invocation, reflog behavior, hooks/configuration policy, and all
preconditions. A host-driven live result is evidence about that bounded path;
it is not evidence that a model selected the Tool.

Task 230 remains **NOT STARTED**. v0.19 release readiness remains subject to
the Task 230 milestone audit. Task 230 must carry forward the limitation:

> MODEL-SELECTED TOOL DISPATCH NOT ESTABLISHED; any host-driven Windows live
> effect certification is a separate assurance claim.

No v0.19 release-ready decision is made in Task 229B.
