# Task 039 plan: v0.4 trusted-profile milestone audit

## Objective

Audit the implemented ADR 0011 trusted-profile boundary after Process Plugin
composition. Establish whether v0.4 can enter release preparation without
adding new authority, provider kinds, or release work.

## Steps

1. Inspect the working tree, checkpoint history, ADR 0011, profile source,
   static loader, effective composer, CLI, provider adapters, documentation,
   and package metadata.
2. Trace the actual authority, permission, registry-publication, lifecycle,
   cleanup, redaction, resource-bound, and platform paths in code and existing
   deterministic tests.
3. Compare every durable ADR invariant with direct evidence. Classify claims as
   verified, implemented, planned, or deferred; do not promote adapter-local
   evidence into mixed-provider evidence.
4. Add only a small regression test and fix if the audit finds a production
   defect in an intended invariant. Otherwise record narrowly scoped missing
   verification as a release blocker.
5. Correct only factual documentation discovered by the audit, write the
   milestone audit, run the requested workspace gates, inspect the final diff,
   and make the A/B readiness decision.

## Boundaries

- No new authority class, provider type, profile command, release preparation,
  version bump, tag, or Codex upgrade.
- Preserve the v0.3 `codex-cli 0.148.0` baseline.
- Do not claim Unix execution or live Codex/profile validation unless run.
