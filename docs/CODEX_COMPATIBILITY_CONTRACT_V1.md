# CodexCompatibilityContractV1

Normative design under [ADR 0034](adr/0034-artifact-bound-codex-compatibility-admission.md).
Accepted 2026-10-06; not implemented by Task 510C1.

## Capabilities and layers

REQUIRED failure rejects the runtime. CONDITIONALLY REQUIRED becomes required
when the trusted host enables the named RAH feature. OPTIONAL absence never
blocks ordinary use. Runtime/provider metadata cannot choose the profile.

| Layer / capability | Class | Required evidence |
| --- | --- | --- |
| L1 executable/resolution/integrity | REQUIRED | Resolved executable bytes, platform and minimal distribution witness |
| L1 companion/resource | CONDITIONALLY REQUIRED | Every component used by an enabled required path; code-mode host for the observed 0.160.0 Tool/code-mode path |
| L2 typed schema/framing | REQUIRED | Method unions, requests, results, notifications, refs, required types and consumed enum alternatives |
| L3 initialize/initialized and dispatch | REQUIRED | Actual candidate accepts handshake, correlates responses and rejects invalid dispatch |
| L4 thread/start, turn/start, active readiness, text stream, terminal and interrupt | REQUIRED | Actual candidate with scripted local provider; neutral lifecycle regression suite |
| L4 owned shutdown/reap | REQUIRED | Probe main and companion shutdown, bounded cleanup, no pending replies/tasks |
| L5 dynamic Tool declaration/call/result/continuation | CONDITIONALLY REQUIRED | Host Tools enabled: typed schema plus actual-executable scripted round trip |
| L6 error/diagnostic mapping | REQUIRED | Typed error envelope and sanitized neutral projection; deterministic local failure |
| L7 model/list and explicit model/provider selection | REQUIRED | Typed interface, local dispatch/catalog result, selector/config reflection |
| thread/resume and resumed event delivery | CONDITIONALLY REQUIRED | Existing-history resume enabled: typed schema, dispatch and local resumed lifecycle |
| Tool image content (`inputImage`, `imageUrl`) | CONDITIONALLY REQUIRED | Enabled host Tool output variant: schema and scripted content/result witness |
| Reasoning/image/audio input, audio output, namespaces, deferred Tool loading, realtime, account management | OPTIONAL | Unused in ordinary restricted RAH profile; unsupported executable requests denied |
| Display label/default/reasoning metadata | OPTIONAL | Validate types if consumed; picker requires selector only today |
| Reported CLI version | OPTIONAL evidence | Bounded diagnostic string, no predicate on version membership |

The default production Codex composition with host Tools therefore requires L5.
Tools-disabled composition may mark it NotApplicable, but cannot later enable
Tools on that verdict. Resume and output profiles must reflect actual callers;
an enabled existing feature cannot be silently demoted to optional.

## Typed protocol surface

Current terminology comes from adapter source and retained generated app-server
schemas, including 0.160.0 `v2` definitions. Schema filenames are discovery hints,
not authority: resolve method discriminators and referenced types structurally.
No substring matching. Parse JSON Schema refs, object required sets, arrays,
nullability, scalar types, unions, enum discriminants and constraints. Reject
unresolved refs, unsupported relevant schema constructs and ambiguous required
alternatives as Indeterminate. Malformed schemas and definite type/method drift
are Incompatible. Bound recursion, reference count and total input bytes.

Validate both directions: every RAH-emitted request must be accepted by a
supported request branch, and every candidate-emitted consumed result/event
must be safely interpreted. Extra optional fields or unused variants may be
ignored; a new required request field with no RAH value is a failure. Do not
require unrelated upstream-required response metadata that RAH does not consume.
Reject unknown lifecycle status at use; a schema permitting unknown consumed
status alternatives without a safe mapping cannot earn a complete pass.

All client requests use integer IDs generated by RAH; replies must echo them.
Server request IDs support string or signed integer and must be echoed exactly.
Notifications have no ID. Stdio is newline-delimited JSON objects; Codex's
current dialect omits `jsonrpc`. Do not require a literal `jsonrpc:"2.0"` field.
An envelope must unambiguously be request/notification/result/error; result and
error together, invalid IDs, malformed framing and mismatched correlation fail.

In the table, fields listed as required are **RAH contract requirements**;
some upstream schemas permit omission. Nullable/optional forms must remain
valid when emitted/consumed by RAH. Schema admission must also validate all
other fields RAH actually sends in the active profile.

| Method/event and form | Request/notification shape | Result / consumed alternatives |
| --- | --- | --- |
| `initialize`, client request | `clientInfo:{name:string,version:string}`; optional `title:string|null`; `capabilities` when sent: `experimentalApi:boolean`, `requestAttestation:boolean` | Correlated object result; current `userAgent:string`; other startup metadata not authority |
| `initialized`, client notification | Object params, no ID | No result; subsequent methods accepted only after handshake |
| `model/list`, client request | Optional `limit:uint32|null`, `includeHidden:boolean|null`, `cursor:string|null`; current RAH sends 100/true | Object with `data:array<object>`, each consumed `model:nonempty bounded string`; `nextCursor:string|null` |
| `thread/start`, client request | Optional upstream fields required when sent by RAH: `cwd:string`, `model:string`, `modelProvider:string`, `approvalPolicy:"never"`, `sandbox:"read-only"`, `serviceName:string`, `config:object`; probe `ephemeral:boolean`; conditional `dynamicTools:array` | `thread:{id:nonempty string}` plus `model:string`, `modelProvider:string`, `cwd:absolute-path string`; effective selection/context must match; consumed sandbox is read-only |
| `turn/start`, client request | `threadId:string`, `input:array` containing `{type:"text",text:string}`; `text_elements` omitted/default empty; when sent `approvalPolicy:"never"`, `sandboxPolicy:{type:"readOnly"}` | `turn:{id:string,status:TurnStatus,items:array}`; admission acknowledgment does not imply active cancellability |
| `turn/started`, server notification | `threadId:string`, `turn:{id:string,status:"inProgress",items:array}` | Matching active thread/turn only; establishes provider-backed active readiness |
| `item/agentMessage/delta`, server notification | `threadId:string`, `turnId:string`, `itemId:string`, `delta:string` | Ordered streamed text; no fabricated Tool lifecycle |
| `item/started`, `item/completed`, server notifications | `threadId:string`, `turnId:string`, `item:object` with `type:string`, `id:string`; agent message `type:"agentMessage"`, `text:string` when consumed | Additive nonexecuting items may be ignored; shell/file/MCP execution items remain unsupported; dynamic Tool item notifications are not host execution proof |
| `turn/completed`, server notification | `threadId:string`, `turn:{id:string,status:TurnStatus,items:array,error?:TurnError|null}` | `completed` -> neutral completion, `interrupted` -> `Stopped/Cancelled`, `failed` -> typed/sanitized failure; `inProgress` is not terminal |
| `turn/interrupt`, client request | `threadId:string`, `turnId:string` | Correlated object result (currently empty); success alone does not prove cancellation; require matching terminal `interrupted` |
| Tool declaration inside `thread/start` | Flat function: `name:string`, `description:string`, `inputSchema:JSON-schema value`; when sent `type:"function"`, `deferLoading:false` | Validate tagged/legacy accepted branch by schema and actual dispatch, not CLI version. Namespace/deferred support is unused |
| `item/tool/call`, server **request**, not notification | `threadId:string`, `turnId:string`, `callId:string`, `tool:string`, `arguments:JSON value`; optional `namespace:string|null` (non-null denied) | Exact ID result `{success:boolean,contentItems:array}`; text item `{type:"inputText",text:string}`; conditional image `{type:"inputImage",imageUrl:string}` |
| `error`, server notification | `threadId:string`, `turnId:string`, `error:TurnError`, `willRetry:boolean` | Failure mapping preserves typed local cause; retry hint never authorizes RAH replay |
| JSON-RPC error response | Matching ID, `error:{code:integer,message:string,data?:JSON value}` | Preserve code/typed source privately; sanitize message/data; unknown-method invalid dispatch in current dialect is `-32600`, not an assumed LSP `-32601` |
| Shutdown | No invented `shutdown` or `exit` RPC | Adapter owns transport close/termination and process/task reap. Verify actual process lifecycle |

`TurnStatus` consumed vocabulary is `inProgress`, `completed`, `interrupted`,
`failed`. `TurnError` requires `message:string`; optional
`additionalDetails:string|null`, `codexErrorInfo:string|tagged-object|null`.
Consumed `codexErrorInfo` examples include `unauthorized`, `usageLimitExceeded`,
`rateLimitExceeded`, `contextWindowExceeded`, `badRequest`, `other` and tagged
`httpConnectionFailed`, `responseStreamConnectionFailed`,
`responseStreamDisconnected`, `responseTooManyFailedAttempts` containing
`httpStatusCode:uint16|null`. Validate existing Task 498 mappings; preserve
unknown diagnostic variants as typed generic provider failures without granting
authority. Do not mistake diagnostic enum extension for lifecycle status support.

Restricted `config` values must preserve disabled shell/unified-exec/memories,
web/image/app and external MCP paths. Unknown compatible runtime must accept
and honor this restriction profile; schema acceptance is supplemented by the
local no-unexpected-execution witness and existing denial regressions. Config
reflection alone is not a proof of OS isolation or malicious-binary safety.

If resume is enabled, also require `thread/resume` request with string thread
identifier and the restricted model/cwd/config overrides actually used, result
with matching `thread.id` and effective model/provider/cwd, and local resume
event delivery. Additional optional protocol fields do not enter admission.

## Deterministic dispatch and behavioral witness

Use two independent fixture tiers:

1. Adapter-owned app-server emulators and mutated schemas verify validator,
   correlation, translation and negative paths. They are offline regression
   tests, **not executable admission evidence**.
2. Run the concrete candidate distribution against a private loopback scripted
   Responses peer. The peer returns fixed SSE frames and inspects requests;
   it has no model, credentials, account, internet dependency or Tool discretion.
   This actual-executable witness is required for L3/L4 and active L5.

Use a private disposable home/cwd and host-configured custom Responses provider
with loopback base URL, `requires_openai_auth:false`, no credential env key,
websockets disabled, retries zero, bounded idle timeout and fixture model ID.
Do not inherit auth, proxy/provider routing, user profiles, project instructions
or MCP/app settings. All production user model choices remain untouched.
Provide bounded offline model metadata for the fixture selector where needed;
that seed is harness data, not real model advertisement/entitlement evidence.
Observe actual requests reaching the owned peer. If effective routing cannot
be established, required evidence is NotObtained. Never contact a real provider
to rescue the compatibility gate.

Sequence in one disposable app-server, separate ephemeral probe threads:

- Initialize/initialized; model/list must dispatch and return a typed local
  catalog; thread/start must accept restricted payload and reflect exact
  probe model/provider/cwd. Invalid method and invalid params must return
  correlated typed errors (current unknown method `-32600`, invalid params
  `-32602`); duplicate/foreign response regressions cannot authorize a turn.
- Text turn: scripted `response.created`, text item/delta/done and
  `response.completed` produce matching turn/started, streamed text and one
  completed terminal. Validate ordering/correlation, not elapsed sleeps.
- Cancellation turn: peer acknowledges receipt and holds its stream open on
  a host-controlled barrier. Wait for matching `turn/started` with `inProgress`
  AND peer request receipt; then send interrupt. Require acknowledgment and
  matching terminal `interrupted`, neutral Cancelled exactly once, no later
  successful completion and no executable Tool after revocation. Release and
  close fixture stream on teardown. Do not run a shell sleep or live model.
- Tools enabled: declare one in-memory bounded test Tool with fixed private
  alias and object input. Peer emits fixed `function_call` for that advertised
  alias (arguments encoded as JSON text on Responses wire); actual app-server
  must emit `item/tool/call` with parsed JSON arguments. Route through ordinary
  host Tool port/registry, return `inputText` with a sentinel, then verify next
  outbound provider input contains the matching function result. Peer emits
  final fixed text; require one host request/execution/result and completion.
  If active runtime configuration routes Tools through code-mode, exercise
  that actual path using an adapter-owned bounded code-mode fixture, and
  require the resolved companion; a direct-only witness cannot prove it.
- Failure turn: scripted local error response exercises current consumed
  TurnError/error event mapping. Adapter fixtures separately cover auth/quota,
  model absence, malformed envelopes and secret-bearing diagnostic fields.
- Shutdown: stop main/owned companions, close peer, reap processes and join
  tasks within deadline even on failure. Abort never becomes a compatibility
  pass; keep local failure evidence without exposing raw provider content.

`ModelRequestStarted` is local/logical admission, not cancellability. Early
`turn/started` arriving before the turn/start response must be retained and
matched once IDs are known. Stale/wrong-thread/wrong-turn started events cannot
unlock cancellation. An early interrupt rejection is not a terminal Cancelled.

Schemas expose dynamicTools, DynamicToolCallParams/Response and ServerRequest
`item/tool/call` deterministically; no general startup Tool-support report is
established. Schema presence proves shape only. The local scripted round trip
proves dispatch/continuation without a model choosing a Tool. Upstream 0.160.0
tests already use a mock Responses sequence for this path; the RAH probe must
exercise the real packaged binary on Windows, not import Codex Rust crates.

Residual risk: local active-turn cancellation cannot prove remote service
availability, every server timing race or remote effect rollback. This design
requires the strongest local discriminator rather than accepting that gap as
schema-only proof. If either certified Windows control cannot run the bounded
local witness, C2 stops before replacing admission; no live-model substitute.

## Distribution discovery and evidence

Do not assume every future runtime consists of two files. Do not hash/admit
the npm tree. Discover requirements for the enabled capability profile through:

| Source | Acceptable inference | Limit |
| --- | --- | --- |
| Runtime manifest (`codex-package.json`) | Parse layoutVersion, target, entrypoint, resourcesDir/pathDir and any future typed component roles | Current layoutVersion 1 manifest has no exhaustive required-component list; resource directory presence is not a component requirement |
| Platform/launcher package metadata | Bind target/provenance and package-relative executable location | A package file listing is not proof every file is runtime-required |
| Startup capability/component report, when available | Typed role/path/feature requirement corroborated by resolution and local use | Report is untrusted data, not permission; no such complete report established for current controls |
| Exact startup/local capability warnings/errors | A specific missing required role/path establishes a missing component for that active path | No arbitrary substring admission; adapter-owned structured classifier of retained evidence, otherwise Indeterminate |
| Package-relative resolution and actual local witness | Resolve component selected for required path, verify concrete bytes and observed process/resource provenance | No silent PATH/npm/resource fallback outside measured distribution |

Current 0.160.0 evidence: executable plus code-mode host were required for the
observed Tool/code-mode path. Source resolves the host from bundled resources
first, then package bin/standalone/current-executable sibling. The manifest
alone does not prove which host gets used. Resolve with that precedence and
measure the actual selected file; conflicting hints or an unmeasured selected
companion cannot pass. Do not hardcode those filenames as an exhaustive future
set. A host-disabled profile need not require an unused code-mode feature.

Discovery algorithm: parse bounded typed metadata if present; derive main and
known profile role locations; use any supported typed component report; reconcile
resolution metadata with actual local required-capability execution. Freeze or
retain checked identities for the minimal members used. Verify the capability
witness from that distribution with ambient resolution disabled/controlled;
record companion process/resource provenance. Required non-system resources
opened for these paths must have a role and identity; optional caches, logs and
probe-home files are harness state, not admitted distribution members.

If a future manifest/report declares a new required role, validate its bounded
package-relative resolution and include its identity generically; no version
allowlist edit. If only an exact missing-file diagnostic identifies the role,
record a typed missing-component failure. Do not automatically fetch files,
scan the whole package tree, execute suggested commands or replay a user turn.
If role/resolution/completeness cannot be established for the required local
paths, Indeterminate. Unsupported metadata versions do not optimistically reuse
layoutVersion 1. No manifest may nominate arbitrary absolute/traversal paths or
grant execution outside host-selected distribution; validate Windows reparse,
symlink/canonical root and duplicate-role behavior.

`exists` requires a regular readable file inside the approved distribution,
appropriate executable target where relevant, canonical resolution, identity
measurement and successful actual use for a required executable role.
`missing` requires a declared/proven active requirement plus absent exact resolved
file, or exact runtime failure corroborating absence. An unreadable file is
Indeterminate; an absent proven required component is Incompatible. Merely not
finding an optional npm file is neither failure nor requirement discovery.
Inconsistent resolution or changed measured bytes fails closed.

## Catalog, result and budget rules

Catalog selectors use `model`, not display `id`. Retain current bounds (100
entries, 256 bytes per selector, current safe selector character set), deduplicate,
and require explicit complete-page evidence (`nextCursor:null`) for current
RAH absence decisions. A paginated catalog cannot prove selected-model absence;
C2 must either finish bounded pagination or preserve catalog failure/not-checked,
without labeling the runtime incompatible solely because a model is absent.
An empty well-formed catalog is an interface pass, not provider readiness.
Display metadata and a particular model name are not admission requirements.

Separate local interface pass from production catalog invocation. A valid remote
auth/quota/provider error is an interface-compatible failure, reported separately;
malformed result from a required local fixture is protocol failure. External
catalog failure, advertisement and entitlement remain distinct under Tasks
499/509. Persisted `provider=openai` retains Codex upstream OpenAI semantics.

Overall Compatible = all active required local capabilities Pass. Incompatible
= any definite required contract failure. Indeterminate = no definite failure
but some required evidence missing, aborted, unreadable, contradictory or
unintelligible. Contradiction with a definite violation is Incompatible;
unresolvable provenance contradiction is Indeterminate. Both block admission
or select a separately verified fallback before conversation creation.

Cold-gate target: at most 30 seconds total including hashing/schema/local
witnesses; each RPC at most 5 seconds within that shared deadline; cleanup an
additional maximum 5 seconds. No sleeps, prompt retries, account checks or
multi-minute certification sequence. Bound schema input at 16 MiB, 64 KiB per
wire message, 1 MiB transcript, 32 required distribution members, 8 local
provider exchanges and 8 probe threads. Oversize/timeout yields Indeterminate,
not Compatible. C2 measures Windows controls and reports observed durations;
if controls cannot meet the design budget, stop and revisit the budget explicitly.
Warm positive cache still verifies artifact identities; target under 2 seconds
on control hardware, with measured results rather than a promised performance
claim. Do not skip hashing for that target.
